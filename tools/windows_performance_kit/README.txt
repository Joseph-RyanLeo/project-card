Project Card Windows 卡顿诊断工具（2026-10-02，第2版）

运行环境：Windows 10/11，自带 Windows PowerShell 5.1。

【启动】
1. 先从更新后的项目导出新Windows游戏；解压工具ZIP，把这三个文件放到新游戏EXE旁。
   此工具直接启动新EXE，不传--main-pack；不要使用上次的Run-PerformanceFix.cmd。
2. 先退出已有游戏，再双击 Run-Diagnostics.cmd。不要双击游戏本身。
   也可以把游戏主 EXE 拖到 Run-Diagnostics.cmd 上；不要选 .console.exe。
3. 出现多个 EXE 时，按编号选择要测试的版本。
4. 工具会打开游戏。将游戏设为 1080p 窗口；进入同一局约72张卡的收藏。
   若有“继续游戏”，用它恢复卡顿的那一局。保留控制台窗口。

【按顺序操作，每一段结束都在游戏里按 F10】
1. 空闲：保持准备界面10秒，按 F10。
2. 收藏：来回翻页10次，等翻页动画结束，按 F10。
3. 卡包：进入商店，只来回指向卡包15秒，先不购买/刷新/离店，按 F10。
4. 随从：离店，拿起一张未刮符文的随从，来回经过战场中的几张随从15秒；
   按右键放回，再按 F10。
   随从和装备统一用长按拖动，便于比较；测试中不切后台、不打开暂停菜单。
5. 装备：拿起装备，沿相同路径移动15秒；按右键放回，再按 F10。
6. 战斗：开始一场战斗，正常等到结算界面，再按 F10。
最后退出游戏。控制台会自动打包并显示 Diagnostic-日期-编号.zip 的位置。
把这个新生成的 ZIP 发回；不要把最初下载的工具 ZIP 发回。
若少做/多做了步骤，请一并说明；不要让游戏处于后台进行测试。

【会收集哪些文件】
- hardware.json：Windows版本、CPU、显卡型号/驱动、内存、桌面显示模式、
  本次游戏 EXE 的名称与 SHA256。桌面分辨率不等于游戏窗口分辨率。
- performance/：本次新生成或被改写的 F10 JSON。不会混入历史日志。
- game-engine.log / game-stdout.log / game-stderr.log：本次游戏的引擎日志。
- process-samples.csv：每秒记录该游戏的CPU时间、工作集和私有内存。
  CPU百分比以一个核心为100%，多核工作可超过100%；不是整机CPU占用率。
- run-before.json / run-after.json：这款游戏测试前后的本局存档（存在才收集），
  便于复现实际收藏、商店和阵容。
- session.json：起止时间、退出码、F10文件列表。
不安装软件、不要求管理员、不改变系统设置、不自动上传、不读取屏幕。
环境变量只在工具启动的进程内生效，结束后恢复。

【无法生成 F10 JSON】
F10要在游戏窗口有焦点时按，有些键盘需要 Fn+F10。
本工具兼容现有带F10采样器的最新导出包，不包含新的游戏EXE。
若程序报告0份F10日志，请先把已生成的ZIP发回，并说明按F10有没有状态提示。
正常位置：%APPDATA%\Godot\app_userdata\Project Card\logs
如果游戏提示的日志位置不同，请一并提供。
本工具已经过文件结构/打包检查；已收到 Windows 10 / PowerShell 5.1
实机生成的完整采集目录，硬件查询、启动、F10和进程采样链路得到确认。
