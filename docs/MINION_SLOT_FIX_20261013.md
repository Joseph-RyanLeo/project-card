# 随从槽位与天赋层级修正（2026-10-13）

## 功能整体如何运作

旧表卡面圆点被直接写为特殊槽数，造成晨昏元素只有1伤势槽、矿石鉴定师只有2符文槽。此次清除银月20张、铁壁21张随从的伤势／纹章数量覆盖；矿石鉴定师补为3符文槽。当前89张随从均按以下通用规则显示、获得和结算：除明确特殊说明外，3符文槽；I／II各2伤势、2纹章，III各3，IV／V各4。原始表格快照只留作来源记录。

读档先校验旧数据，随后迁移实例槽数与合法布局，再恢复拥有权、阵容、工作包，成功后立即保存新标记。旧符文、揭晓、付费擦痕、元素贴纸、永久成长和可容纳状态保持；新增符文槽未揭晓，元素由实例身份确定，不消耗本局随机流。超额纹章沿用整卡返还；超额伤势在当前开发模式整卡退回工具箱，正式模式按此前规则清除。若工具箱容纳不了返还物，载入被拒绝，原文件不会被覆盖。

敌方有主存档集合与路径遭遇快照两处持久状态，两者都同步迁移。新增遭遇带版本标记；旧遭遇恢复后重新编码为新快照，不重抽原有随机内容。

战后统计原在3500层，高于2400层的路径／天赋面板。统计改至2000层，保持覆盖普通卡牌，并让流程面板、商店和检视按已有层级覆盖它。天赋面板原有透明度保留，背后统计会一同被压暗；玩家统计仍在面板外正常显示。无需另加一套临时隐藏逻辑。

## 关键脚本与数据

- `CardSlotLayout.get_default_counts()`集中定义2／2、3／3、4／4；卡牌资源的`wound_slot_count`与`emblem_slot_count`省略时默认`-1`，表示使用通用规则。明确特殊卡仍能使用覆盖与固定布局。
- `CardData.runes`是卡面槽位定义；`OwnedCard`保存真实元素、刮擦、揭晓、贴纸、纹章和伤势，不能把实例状态写回共享卡牌。
- `RunSaveService`的存档版本9、槽位迁移标记2区分旧数据与已迁移数据。迁移补槽只允许旧随从1／2槽且各数组长度一致；新版损坏数据仍拒绝，不用补槽掩盖错误。
- `EnemyEncounterBuilder.restore()`复用同一迁移入口，并返回规范化快照；`ShortMazeController.restore_state()`在正式恢复后将它写回路径数据。
- `SquadView.BATTLE_RESULT_OVERLAY_Z_INDEX`控制战后统计；天赋继续由`ShortMazeController`的既有流程面板负责。

## GDScript写法说明

`-1`是“采用默认规则”的标记，不是负数容量。省略资源里的显式数量，Godot会使用脚本字段初值，之后读取集中规则；修改品级后无需手动同步两种槽数。

`duplicate()`在补槽前复制数组，`duplicate(true)`额外复制里面的贴纸字典，避免校验或失败的迁移改坏输入快照。新槽的随机数生成器以实例身份的`hash()`设定种子，因此同一存档反复载入得到同一元素；这是迁移时新增内容的固定结果，不会改变已获得符文。

`z_index`参与绘制排序，子节点默认累加父节点的层级。回归检查累加真实父节点层级，验证实际统计低于面板；统计层本来就忽略鼠标，因此不改变天赋点击逻辑。
