## 伤势实例与系统边界

- **数据与存档：** `CardData.wound_slot_count` 定槽数；`CardSlotLayout` 生成/校验布局；`OwnedCard.wound_slots` 保存每个实例的槽状态，`set_wound_slot()` 修改状态，snapshot/restore 保存读回。`RunSaveService` 处理旧槽数和布局迁移；正式模式超额伤势按当前迁移路径清除，测试模式可返还到迁移记录。伤势状态不是共享 `CardData` 上的玩法属性。
- **显示与工作区：** `EmblemLibraryData.get_wound_definitions()` 从 JSON 读取类别为伤势的目录项；`StatusIndicatorStyle` 负责图标与别名；`main.gd` / 检视卡界面把伤势拖放到伤势槽；`EmblemLibraryView` 对伤势隐藏刮刀。已有槽位/UI 测试覆盖拖放分区、贴纸显示等流程，不证明每条目录规则成立。
- **显现、遮挡与遮蔽：** `SquadData.get_visible_wound_slots()` 按卡牌叠放遮挡筛选。`BattleController._register_formation_wounds()` 只注册显现伤势；行动值伤势静态修正会按 `BattleSquadState.get_unmasked_active_injuries()` 过滤遮蔽中的槽。解除一个遮蔽来源后，若仍有另一来源则保持遮蔽；最后一个来源解除后数值恢复。行动公式来源也只列出当前生效的显现伤势。
- **遮蔽与结算：** `BattleSquadState` 以 `instance_id:wound:slot` 追踪伤势、等级和多个遮蔽来源。随军医者等规则可把被遮蔽槽排除出候选；战斗变更账本记录变更，`BattleSettlementService._apply_random_squad_wound_heal()` 从提交的小队实例中随机清除一个未遮蔽非空伤势槽，最多移除一处。此处是“暗元素碎晶/奖励伤势移除”通路，不是暗蚀伤势效果。
- **战后新增伤势：** `GAMEPLAY_DESIGN.md` 规定小队整体只进行一次50%判定，复活不重试，并说明新伤势立即生效；`BattleController` 中有显现槽、遮挡筛选与账本登记代码。当前阶段未找到覆盖全部候选优先级、升级规则、复活和正式战后保存组合的完整验证，因此这些规则仍需逐项核对，不能由单个脑死亡测试外推。

## ID 别名与文档冲突

- 目录当前用中文名称作 ID；UI 兼容映射包括 `poison_1/2/3`、`concussion`、`blind_1/2`、`fracture_1/2`、`light_blood`、`internal_1/2/3`、`tear_1/2/3`、`frozen`、`feather_1/2`、`crystallization`、`dark_erosion`、`confusion`、`burn_1/2`、`brain_death`、`poisoned`→尸毒Ⅰ、`greed`、`magic_mark_1/2/3`。另有 `fracture`→骨折Ⅰ；`brain_death` 也在触发定义中作为脑死亡别名。羽毛别名映射到纹章，不计入29种伤势。
- `GAMEPLAY_DESIGN.md` 的通用规则、`docs/CARD_CHARACTER_DESIGN.md` 的具体伤势与 `OwnedCard` 当前数据结构覆盖了伤势槽、遮挡、伤势存档和战斗结算框架；目录里不少文字仍是未审阅初版。若目录词条与已经确认的设计条目含义不同，应由设计确认规则后再实现。
- 全局刮刀解锁、正式开局开放条件、可移除伤势的具体事件仍标为待设计；当前开发检视工作区隐藏刮刀属于编辑工具限制，不等于正式准备阶段的伤势移除系统已经实现。
