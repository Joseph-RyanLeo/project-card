# 基础图鉴光泽与工艺参数保存修复

日期：2026-11-03。依据用户反馈修复基础图鉴出现特殊光泽，并将碎闪纹理设为15、补齐开发工具的工艺参数保存。只在主目录main工作，未提交或推送。原有余烬侍从资源改动保留，未改玩法或玩家存档。

## 结果与使用方式

- 基础图鉴保持普通卡面、普通卡图，只保留整卡透视倾斜；没有扫光、碎闪、法线浮雕或全息。卡牌品级原画中的金色边框仍是原图的一部分。
- 实际收藏继续按完整OwnedCard外观显示，银／金／彩闪、法线、碎闪及全息／超框组合不被普通图鉴规则覆盖。
- 项目碎闪纹理密度已设为15；全息和法线仍各自保持原默认纹理32，强度0.75，全息景深2.5。
- 在卡面调整器中选择工艺、修改强度／景深／纹理后，点击顶部“保存工艺参数（全局）”。切换工艺保留各自草稿；“重载工艺参数”放弃工艺草稿，读取真实磁盘值。底部“保存卡牌修改”和“保存到所有罕贵度卡面”继续负责单张CardData资料与取景。
- 工艺参数保存在`resources/ui/card_finish_settings.tres`，是工程共享的显示配置，随工程分发，不是玩家存档或单张卡牌属性。已经打开的旧开发工具需退出后重新进入，以加载新增控件与逻辑。

## 一、根因与显示／保存流程

### 基础卡为什么有时带光泽

基础图鉴直接绑定CardData，没有OwnedCard。`CardView._refresh_owned_appearance()`原先遇到“无实例、无工艺控制器”就提前返回，但检视表面已默认开启金色扫光。因此首次从基础图鉴初始化共享悬停画布、或新建基础卡检视时，默认光泽没有被普通材质覆盖；共享画布先前是否显示过实际收藏，也会影响表现。

修复删除了这条过早返回，保留原有“没有合成表面且无需特殊材质时不创建控制器”的优化。只要已经绑定检视表面，无实例的卡也走同一刷新入口，明确设置普通卡面／卡图，并关闭不适用效果。复用画布时同样重置，避免残留上一张特殊卡的状态。

真实GPU对照使用相同卡内合成纹理和相同透视，临时开启旧扫光生成反例，再关闭它生成修复图；卡内像素内容一致，外层结果不同，确认不是原画自带光泽或采样问题。反例只存在测试画面中，没有写入卡牌。

### 工具为什么无法保存纹理

原工具的`FinishStrengthSpin`、`FinishDepthSpin`和`FinishDensitySpin`只赋值给本次会话的`CardFinishPreview`。原保存函数只写CardData的可编辑字段与各工艺取景偏移，根本没有工艺参数的持久化路径；当时说明也写着“工艺仅作预览”。因此不是用户操作错误，也不是这次发现了文件权限拒绝。

现在工艺控件先改按工艺分组的预览草稿，点击顶部全局保存后，读取磁盘最新配置、合并真正改过的工艺，再用ResourceSaver写入原生Resource。成功后才清掉脏标记、提示成功并通知真实卡面刷新；失败保留草稿和明确错误信息。卡牌保存与工艺保存各有独立入口，避免一张卡牌的编辑按钮悄悄改变整批材质。

真实卡面从共享配置分别取得卡面工艺和卡图工艺的参数。碎闪＋全息组合中，碎闪晶片密度使用15，全息压纹仍使用32，互不串改。

## 二、数据、脚本与职责

- `scripts/ui/card_view.gd`：绑定合成表面后统一刷新外观；无OwnedCard的基础图鉴明确恢复普通，真实卡面启用已保存的共享参数。
- `scripts/ui/card_finish_settings.gd`：原生Resource脚本，保存全息、法线、碎闪的适用强度／景深／纹理字段；归一化输入范围，按工艺读取／写入参数。
- `resources/ui/card_finish_settings.tres`：共享显示配置，`fractured_density = 15.0`。
- `scripts/ui/card_finish_preview.gd`：继续承担原有材质渲染，真实卡面读取共享配置，调整器使用未保存的手动预览值。收到配置Resource的`changed`信号后刷新已经存在的真实卡面。
- `scripts/tools/card_art_tuner.gd`：`_finish_settings`是打开时的配置基线，`_finish_drafts`是各工艺草稿。`_load_finish_controls()`恢复所选工艺，`_save_finish_settings()`合并并保存，`_reload_finish_settings()`放弃工艺草稿。卡牌草稿与保存函数保持原职责。
- `scenes/tools/CardArtTuner.tscn`：顶部新增全局保存／重载入口，原材质开关和工艺选择仍在原位，底部保留单卡保存。标题文本居中不变，收窄其占位矩形给新入口留出空间。

原有CardData结构不能清晰承载这项配置：工艺风格由所有同类卡面共享，并不是某张卡的数值、取景或拥有实例状态，所以新增独立Resource，不向每张卡牌复制参数。

## 三、需要理解的Godot／GDScript写法

- `Resource`可直接保存为`.tres`，与Godot编辑器和导出资源流程共用，不需要第三方依赖。
- `ResourceLoader.CACHE_MODE_IGNORE`读取磁盘最新版本，不把预览所持旧缓存当成已经保存的结果；保存前合并本次真正改动的工艺，保留其他工艺的磁盘修改。
- `set_value_no_signal()`用于切换工艺时回填控件，避免程序写入控件被误当成用户编辑并制造脏状态。
- `Vector3`在这里仅打包“强度、景深、纹理”三个数，不是空间坐标；只有全息会使用景深。
- Resource的`changed`信号通知已有材质重新读取配置；这只改变显示，不改变OwnedCard外观身份、玩法随机流、发现或收藏内容。
