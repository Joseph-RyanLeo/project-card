# 卡牌纹理调整器

入口：主界面设置 → 开发工具 → 卡牌纹理调整器；对局内仍可从Esc → 开发工具进入。也可单独运行 `scenes/tools/CardTextureTuner.tscn`。

## 使用流程

左侧切换闪纹、全息、法线、碎闪参数，右侧选择工艺和卡牌，鼠标指向预览查看光影。三张不同卡牌复用正式卡面渲染，调整立即预览；点击“保存并应用所有卡牌”才写入全局配置，并刷新已经显示的卡牌。新建卡牌和下次启动读取同一份配置。

右键任意预览卡牌可进入右侧4倍放大检视，移动鼠标观察反光。左侧参数区保持可操作，拖动滑块或输入数值会实时刷新大卡和小卡；两者使用同一份当前草稿，未保存的参数也会显示。右键、Esc、点击背景或“关闭检视”返回调整器，保留参数和未保存状态；在调整器再次按Esc才退出整个工具。

- 闪纹数量／密度：越大光带越密。
- 闪纹位置：平移整组光带，数值相差1对应一个重复周期。
- 闪纹锐度：越大光带越窄。
- 闪纹亮度：控制光带叠加强度。
- 默认反光方向：没有有效鼠标方向时使用；指向卡牌后继续随鼠标转动。
- 随鼠标明暗强度：0关闭；所有非普通卡面或卡图共用。指向中间时整体较暗，指向边缘时整体提亮，同时鼠标附近更亮。人物参与柔光，卡名与数值保持清晰。

磨砂效果与三个磨砂控件已暂时移除。配置中原有磨砂值保留，保存其他参数不会清除它们，但当前渲染不读取这些值。

- 全息：反光强度、前后景深和纹理密度。
- 法线：反光强度和细纹密度。
- 碎闪：反光强度和晶片密度。

银闪、金闪、彩闪共用闪纹参数，碎闪默认叠加白色闪纹；光带在背景与卡框绘制，人物不叠加光带，会参与随鼠标变化的宽柔光；卡名和数值不叠加光带。全息、法线、碎闪继续读取各自参数；全息立绘保留原全息效果。全局生效指所有具有对应工艺的卡牌，包括收藏、战场、悬停、检视和开包；普通卡保持普通外观。卡牌本身使用哪种工艺仍由其拥有实例决定。

“重新载入”放弃未保存草稿，“恢复默认”仅把草稿恢复默认值，仍需保存才全局生效。关闭时未保存的草稿丢弃。读取或保存失败时保留草稿。旧卡面调整器继续负责单张卡的资料、取景和预览，不再承担全局纹理编辑；开包调整器也不再重复覆盖闪纹参数。

## 数据和脚本

- `resources/ui/card_finish_settings.tres`：唯一的全局纹理配置，属于开发美术参数，不属于玩家存档。
- `scripts/ui/card_finish_settings.gd`：声明参数、范围和默认值；`FIELDS`同时供界面创建控件和保存字段使用。
- `scenes/tools/CardTextureTuner.tscn`、`scripts/tools/card_texture_tuner.gd`：独立工具、草稿、三张正式卡牌预览和保存；沿用原卡面调整器的自动资源扫描。
- `draft`是预览副本，`baseline`是开始编辑时的磁盘值。保存时重新读盘，只合并本次改动字段，保留其他未编辑字段的外部修改。
- `card_finish_preview.gd`：正式卡面默认读取共享资源；工具预览指定草稿作为来源。保存成功后通过资源的`changed`信号让现有卡面刷新。
- 放大检视复用`CardInspectionOverlay`和`InspectionCardSurface`，由调整器持有检视外壳并处理关闭，关闭过程只释放检视节点，不重新载入草稿。
- `card_finish.gdshaderinc`：闪纹的唯一计算公式；`card_frame_foil.gdshader`和`card_art_finish.gdshader`分别在卡框与背景绘制同一光带，角色由原图透明轮廓自然遮挡背景反光。外层只做整体透视，避免整卡再叠一次光。静置无需新增离屏画布。
- `_change()`更新草稿后同时刷新三张小卡与当前大卡。右侧检视外壳仅占预览区域，左侧控件继续接收鼠标输入。

## 初学者说明

`Resource.duplicate(true)`复制出独立草稿，所以移动滑块不会提前改变游戏卡面。`emit_changed()`是主动发出资源变更信号：只在磁盘保存成功后调用，各卡面监听一次后自行刷新，无需遍历每张卡或重建场景。`CACHE_MODE_IGNORE`用于重新读取磁盘资源，防止“重新载入”拿到旧缓存。

保存只更新共享美术配置；卡牌资料、取景及玩法随机流不受影响。调整器预览也使用独立的拥有实例，不向玩家收藏添加卡牌。

## 历史实验：实时检视与磨砂验证（现已停用磨砂）

真实界面专项50项、角色轮廓GPU专项17项、收藏静置与悬停回归85项，共152项通过。轮廓检查在银／金／彩三种闪卡中分别抽样约5000个角色像素，改变亮纹强度时角色与卡名不变，背景和外框均改变；调整磨砂只改变角色。覆盖左侧实际鼠标点击滑块、大卡即时更新、关闭后草稿保留、18种外观组合与静置不创建额外离屏画布。测试只写临时配置，正式配置和卡牌资源未改写。

初学者说明：这里利用Godot原有的节点绘制顺序，先绘制会反光的背景，再绘制带透明轮廓的角色，因此背景光不会盖到角色身上；卡框单独使用相同光带公式。角色颗粒由固定坐标计算，不随时间抖动，也不消耗玩法随机数。大卡和小卡引用同一个`draft`，数值变化时刷新两者的材质，无需关闭检视。

## 历史实验：颗粒大小、密度与固定方向柔光（已由下述修订取代）

流程仍为左侧参数→同一份草稿→刷新大小卡材质，关闭检视保留调整，保存后对全体对应闪卡生效。新增参数的范围和默认值集中在`card_finish_settings.gd`，由现有字段表自动创建滑块与数值框。

`card_art_finish.gdshader`把卡面坐标按颗粒大小划为固定单元，再按密度决定哪些单元出现颗粒；大小控制空间尺寸，密度控制覆盖数量，强度控制明暗对比，三者独立。`card_finish.gdshaderinc`的`card_diffuse_light()`统一计算固定左上柔光；立绘、背景与卡框使用同一个平滑鼠标方向，普通人物只有漫反射明暗，没有额外光带。

初学者说明：`floor()`用来定位颗粒所属单元，同一单元在每一帧得到相同结果，所以颗粒不会乱跳。漫反射使用表面方向与光照方向的点积求亮度，正面保持原亮度，向不同方向倾斜时平滑变化；它与背景／卡框的窄光带分别计算，可以单独关闭。

本轮验证：颗粒与明暗GPU32项、实际调整器操作53项，共85项通过。覆盖三个新增滑块在放大期间真实点击、生效与保存恢复；颗粒参数单独变化、密度0、明暗强度0、光带关闭时人物仍有明暗变化、静置与检视一致、普通卡隔离与用户配置未改写。

## 当前：停用磨砂与跟随鼠标的宽柔光（2026-11-06）

输入仍复用已有鼠标平滑：鼠标居中时卡面较平且整体较暗；越靠边缘倾斜越大，整体逐渐提亮，同时鼠标附近形成宽而柔和的局部亮区。人物、背景、卡框使用同一公式，人物不叠加条形扫光。左侧明暗强度在放大期间实时生效，关闭保留草稿，保存后统一使用。

`card_pointer_light(uv, force, strength)`集中在`card_finish.gdshaderinc`。`force`决定整体亮度和局部亮区中心，`uv`是当前像素在整张合成卡面中的位置，所以立绘和卡框不会各自出现独立光斑。`smoothstep()`让居中到边缘的整体提亮平滑过渡，指数衰减让局部亮区没有硬边。

磨砂纹理计算已从shader移除，控制器不再传递磨砂参数，左侧字段表移除三个磨砂控件；Resource中的旧字段仅用于保存已有配置，不参与渲染。

验证：`card_foil_pointer_light_test.gd`真实GPU41项、调整器原生输入与保存恢复51项，共92项通过。覆盖四个边缘均比中心亮、鼠标所在侧更亮、人物无条纹、旧磨砂值不生效、静置与检视一致、明暗0关闭、普通卡隔离，以及保存保留旧磨砂字段。

参考图观察：仅凭用户提供的单图不能确定原制造工艺或渲染实现。要复现图中细密表面纹路与柔和亮泽，可使用角色遮罩、细纹法线和粗糙度贴图控制宽柔高光，并将背景彩箔分开处理。法线用于改变细部受光方向，粗糙度用于控制反射清晰度与宽度，参见[Filament材质指南](https://google.github.io/filament/main/materials.html)。此处为复现方案，不声称参考图实际使用了这些实现。

## 所有特殊外观与碎闪白色闪纹（2026-11-06）

鼠标柔光扩展到所有非普通卡面或卡图，包括银闪、金闪、彩闪、法线、碎闪、全息和超框；普通卡面搭配全息／超框同样生效。只有普通卡面加普通卡图的组合保持原画。原有全息、法线、晶片、超框效果继续保留；碎闪增加背景与卡框的默认白色闪纹。

控制器分别判断“是否有鼠标柔光”和“是否绘制闪纹”：前者覆盖所有特殊组合，后者覆盖银／金／彩和碎闪。两者使用独立shader开关，避免为全息或法线额外加光带。碎闪的光带颜色固定选白色，继续使用共享密度、位置、锐度和亮度；不会改玩家已保存的参数。

18种外观组合的真实GPU变化、普通组合隔离、晶片保留、碎闪新增光带的白色通道测量共157项通过。


## 磨砂闪／指纹闪实验（2026-11-06）

入口：主界面 → 设置 → 开发工具 → 卡牌纹理调整器。在风格下拉框选择“磨砂闪”或“指纹闪”，左侧自动切到对应参数页。右键放大后左侧仍可实时调整；关闭大卡保留草稿，保存后同工艺的全部卡牌统一生效。卡面调整器也新增两种预览，可单独调整其取景。

- 磨砂闪：固定的细颗粒调制背景和外框的白色反射，人物保留原画明暗。可调膜层强度、颗粒密度和颗粒起伏。它独立于已停用的旧灰噪声磨砂，原来的旧参数仍不参与渲染。
- 指纹闪：人物使用统一的连续弧纹，背景和外框共用连续放射交织纹；可调强度、曲纹密度、弯曲程度、整体方向和虹彩比例。当前是共用的几何分区试验，并非自动识别头、手、武器；要像参考卡一样精确贴合每个肢体，后续需要逐卡标定区域遮罩。
- 新工艺有稳定的实例编号与保存键，但抽取权重暂为0，不改变已确认的开包分布和价格。全息／超框仍可作为独立卡图表现与其组合。原来的普通、银／金／彩闪、法线与碎闪继续沿用原逻辑。

实现流程：鼠标输入继续进入原有`InspectionCardSurface`，同一方向传给卡框、人物、背景；`CardFinishPreview.refresh()`从草稿或共享Resource读取参数，通过`apply_film()`发给三个图层。`card_film.gdshaderinc`生成固定细纹，再依据鼠标位置计算膜层反光；卡名与数值在独立UI层，不覆上刻纹。素材仍是最近邻采样；放大沿用4倍合成，不添加另一套倾斜或模糊。

关键数据：`CardAppearance.Surface.FROSTED / FINGERPRINT`分别对应稳定键`frosted / fingerprint`；`card_finish_settings.gd`内的同名前缀字段保存全局调参。实际磁盘资源仍为`resources/ui/card_finish_settings.tres`，本轮没有改写用户已保存的参数。

GDScript的Resource相当于可序列化的共享参数对象，调整器先复制成草稿，所以未保存的修改只影响预览；保存成功后再通知正式卡面刷新。shader的`uniform`是脚本传入的参数；`fwidth()`估计一个屏幕像素覆盖的纹理范围，小卡下会将过细线条渐变成平均亮度，减少摩尔纹；纹理没有使用时间变量，因此停住鼠标时不会自己跳闪。

GPU截图位于`docs/previews/experimental_card_film_20261106/`；`experimental_card_film_test.gd`覆盖实际渲染、纹理静止、密度调整、右键放大、检视内实时调参、临时磁盘保存与全局刷新，以及实验外观不进入随机池。

验证结果：新工艺GPU／UI25项、原闪卡柔光41项、24组合169项、卡面调整器11项通过。Esc实时调整器首次点击受macOS退出全屏时序影响，临时诊断副本仅增加一次绘制等待与截图后，原51项断言全部通过。新工艺独立专项退出时有资源释放诊断，未影响实际渲染检查。


## 当前人物分层与背景／外框连续纹理（2026-11-07）

磨砂只覆盖背景与外框，人物保留原画和已有鼠标明暗；指纹闪的人物统一使用一个连续弧纹中心。背景和外框共用放射交织纹，眼睛实验的参数页、透光字段、卡牌标注、遮罩缓存与shader分支均已删除，人物恢复正常不透明绘制。

此前外框与背景不同，是因为`card_film_finish()`将外框单独送入斜纹分支。现已删除该分支，外框和背景调用相同的材质分支，使用整卡坐标计算纹理方向、密度、相位与反光。整卡坐标相当于把两个图层放在同一张纸上定位：相邻位置沿用同一套纹理，而不是各自从局部左上角开始。全息背景的原画仍可产生景深位移，指纹底纹使用投影前的整卡平面位置，因此不会随背景取样偏移而与框断开。

相关代码为`card_film.gdshaderinc`的背景分支、`card_art_finish.gdshader`传入的整卡位置，以及`card_frame_foil.gdshader`调用。全局密度、弯曲、角度和反光参数继续共用原设置资源；放大实时调参、草稿和保存流程沿用原实现。

验证通过实际GPU比较正式背景／外框shader：用同样中灰底纸排除原素材色差，逐点比较同一整卡位置的纹理，包含3个鼠标位置及普通／全息两种卡图。截图见`docs/previews/card_film_continuity_20261107/`。取消的眼睛专项与截图已删除；新工艺预览、人物分离和保存继续由`experimental_card_film_test.gd`覆盖。

本次连续性6项与新工艺预览／保存25项合计31项通过；眼睛相关实现和当前界面已无残留。

2026-11-07 后续调整。磨砂闪和指纹闪的亮带共用银／金／彩闪的方向计算。鼠标从卡牌中心移向边缘时，亮带垂直于中心到鼠标的连线。指纹页的「刻纹整体方向」仍只旋转纹理。磨砂反光固定为白色，已移除该工艺的虹彩比例。碎闪页新增「明度」，默认 0.55，取值 0～1，同时缩放晶片高光和背景、外框的白色闪纹。滑块沿用草稿预览、保存及刷新正式卡面的流程。

碎闪页的「饱和度」控制晶片彩色反光与白色的混合比例，默认 0.55。「色相（°）」沿色环旋转晶片色彩，默认 0°，范围为 −180° 到 180°。两项都支持实时预览和保存。
