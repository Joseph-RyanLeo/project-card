## 为什么拆成两张表

卡牌名称、品级、基础数值和完整规则说明天然属于卡牌本身，继续保留在“卡牌审阅”表。一张卡可能同时具有常驻限制、触发效果、持续效果和永久成长；把这些都塞进同一行会形成重复列或不可稳定导入的长文本，因此新增“效果定义”子表并以关联字段连接卡牌。

## 稳定身份

- `card_id`：英文小写蛇形命名，与 Godot `CardData.id` 对齐，例如 `heavy_knight`。显示名、源单元格或卡包调整时不改；废弃后不把旧ID分配给另一张卡。
- `effect_id`：`<card_id>.effect.<两位序号>`，例如 `heavy_knight.effect.01`。序号只负责稳定身份，不代表运行时优先级；效果换行、改名或调整顺序时不改ID，删除后不复用。
- `source_record_id`：飞书卡牌审阅记录ID，只作为同步定位信息，不进入玩家存档。
- `source_cell`：用于发现源表移动或映射异常，不作为稳定身份。
- `schema_version`：当前为2；字段含义发生不兼容变化时才递增。

## 原子效果字段

| 字段 | 作用 |
|---|---|
| `trigger` | 何时进入候选队列 |
| `conditions` | 真正执行前必须全部满足的条件 |
| `target` | 从哪个范围选择或定位对象 |
| `operation` | 对目标执行的唯一主要动作 |
| `value` | 固定值、读属性或公式；骰子沿用统一 `ndx` 语法 |
| `duration` | 瞬时、固定秒数、直到消耗或本局永久 |
| `stacking` | 相同或不同来源如何共存、计数或刷新 |
| `source_owner` | 日志和触发归因到哪一个卡牌／法术／装备实例 |
| `result_owner` | 临时状态或永久变化最终记录在哪个对象上 |
| `parameters` | 不适合扩成通用列、但导入器仍需读取的结构化参数 |

`trigger`、`target`、`operation`、`duration`、`stacking`、`source_owner` 和 `result_owner` 在飞书使用单选字段，避免自由文本产生近义值；`conditions` 使用多选字段；`value` 与 `parameters` 暂用JSON文本承载有类型的参数。等代表样例确认后，再决定是否把高频参数提升为独立列。

## 导入边界

1. 先按 `card_id` 找卡，不按显示名匹配；不存在、重复或为空均停止导入。
2. 每个 `effect_id` 全局唯一，并且必须以所属 `card_id` 开头；一张卡的多个效果通过关联记录聚合。
3. 枚举值必须来自受控选项，导入器不得把未知值静默当成普通文本。
4. `conditions` 按 AND 组合；需要 OR 时拆成两个效果或显式使用组合条件，不靠自然语言猜测。
5. `value` 只描述取值，不隐含目标、持续或叠加。掷骰先求和，条件再比较总和。
6. 永久变化必须填写 `result_owner`；恢复战前快照后只按独立永久记录应用一次。
7. 卡牌规则确认与结构化拆分确认分开；2026-09-16用户确认最终拆分后，38条效果全部已确认，活动提问为0。不得仅凭卡牌的 `review_status` 进入实现批次，也不能因没有提问就自动确认效果。阶段学习验收尚未完成。
8. 效果同步前保存读取快照并比较待写字段；同步后读回核对记录数、关联、ID唯一性、字段类型和选项。效果同步脚本只操作审阅库，源表写入数必须为0；已批准的热诚源表迁移由独立脚本和审计记录管理，不是后续源表写入的常设授权。

## 本轮补充：结束条件与有关联的效果

当前样例扩大到5张卡、6条效果；先核对这一批，再扩展整包。以下约定取代初版将“每场一次”放入叠加字段的方式。

- “中文解读”供人工直接阅读；JSON保存程序参数。
- “效果组”把同一次触发中的多个组成部分归到一起。运行时还需事件实例ID，避免两张同名卡或两次战吼被合成一次事件；定义ID不能代替实例ID。
- “结束条件”说明时间到期或哪个事件移除状态；“结束操作”说明结束时做什么。瞬时金币奖励完成后不撤回金币；移除加成时只撤回对应来源的加成。
- “触发次数限制”独立记录每场次数，与多个加成如何叠加分开。狂战先锋跨场可继续累计成长，每场最多触发一次。
- 辎重驮夫两条效果共用同一次战吼：基础1金币无条件，额外2金币检查当次乡邻；老狼仅额外触发乡邻部分，1名老狼时合计5金币。后来才满足乡邻不补发。
- “指定效果结束后触发另一效果”后续使用 `effect_ended` 触发加关联效果ID，并匹配运行时效果实例。当前没有采用此机制的真实样例，因此暂不生成空关联列；到首次需要时添加。关联前还须明确自然到期、驱散等结束原因哪些符合条件，不能一律视为同一种触发。

本轮没有战斗执行器。结束条件已改为多选（操作结算完成、持续时间到期、指定行动后、来源死亡、装备卸下、乡邻失效、战斗结束、本局结束）；结束条件关系为单选“任一满足／全部满足”，不得沿用启动条件默认AND的约定。结束参数保留文本说明具体对象、次数等；时间到期的秒数以持续参数为准，避免两个数值来源冲突。事件类条件采用“发生过”还是要求当前状态同时成立，复杂效果须另行明确，不自动猜测。结束操作保持独立。下面的初版清单中的4张/4条计数仅为历史批次。

- 4个 `card_id` 和4个 `effect_id` 均唯一，卡牌关联存在且一一对应。
- 改卡牌显示名后仍可凭 `card_id` 找回同一记录。
- 每个效果的八个核心维度都非空，枚举值在允许集合内。
- 狂战先锋的永久成长归实际获得成长的单卡实例，并标明每场最多一次。
- 灰烬战盾的取值使用受击结算后的当前护甲，封顶4，且明确为非行动伤害。
- 战斗怒火只表达已确认的5秒生命下限，不新增优势、命中或硬币语义。
- 导出再导入一次后内容不变化；重复执行同步不新增重复记录。
- 飞书字段类型、枚举选项、视图顺序与列宽保持不变；仅新增字段和新表可按计划出现。
