## 游戏中的获得与使用

普通商店配置开放灰烬证册和银月之章。每个普通卡包先确定主题，再从该主题的合法候选中抽取卡牌，银月包不会混入其他主题。银月小包／大包使用对应包装图，沿用当前商店的3张／5张、12金币／18金币配置及大包至少一张II级的保底；这些是现有商店参数，可在配置中调整。行动方式定向商品沿用开放候选池。

购买后生成真实 `OwnedCard`，进入收藏并沿用揭晓、堆叠、装备、法术准备和保存流程。预言胜利、失败预言与月露标记为衍生，不进入普通抽包池。观星者生成的两张预言通过奖励账本获得，不自动准备或释放。法术按原规则扣耐久，星火术单独声明无限耐久并显示∞。

均衡随从按实际前后排切换行动方式；跨排换位既更新逻辑阵容，也通过信号移动现有卡面节点。换位保留冷却进度。卡图可用项目现有 `CardArtTuner` 继续调整。

## 重点时序与边界

- 瑟兰的远程行动具有近战和远程标签，在真实命中时分别计算，取较高伤害，只写入一次；不会把两类倍率相乘。披风不能闪避该双标签攻击。
- 伊尔突击时按双方每个小队的有效光暗符文净差分别提供永久生命或永久数值；相等不生效。生命归生命来源卡，数值归行动来源卡，本场立即生效、正常战后提交。2026-10-10后续修改取代填纹章。

- 晨昏骑士现为前排眩晕／后排疲劳突击，换排重触所在小队全部突击；五卡最新三场景文案和数值以[BALANCE_ROW_TEXT_20261010.md](BALANCE_ROW_TEXT_20261010.md)为准。月华树人保留木元素身份和木护甲，同时附加暗元素基础收益。

## 实现学习说明

### 1. 从输入到结果

游戏启动扫描卡牌资源 → 商店按开放卡包抽取商品 → 购买创建单卡实例 → 玩家部署、装备或准备法术 → 战斗控制器建立临时小队状态 → 银月运行时响应突击、实际命中、开采、法术释放及时间点 → 控制器统一处理目标、弹道、伤害与死亡 → 正常战后账本提交永久成长与奖励，清理临时状态。

这样组织后，银月只提供内容规则，已有伤害倍率、元素派生、随机源、死亡顺序和存档仍只有一套执行入口。卡面收到状态和阵容信号后更新，无需靠动画回调决定伤害何时生效。

### 3. 需要单独理解的GDScript写法

- `Array[BattleSquadState]`、`Array[Dictionary]` 是带类型的数组。它们让编辑器提前发现把资源或单卡误当成战斗小队的问题；从JSON等无类型数据建立类型数组时使用 `assign()`，避免整份无类型数组直接赋值引发类型错误。
- `RefCounted` 用于不需要独立场景节点的内容服务。它通过引用计数释放；运行时清理时必须断开 `kill_resolved` 信号并清空持有状态的容器，避免控制器、信号和运行时互相保留。
- 遮蔽用“来源ID → 到期时间”，追加行动用显式事件标记。这样多来源可独立撤回，同来源可以刷新，复制／追加不会再次递归生成自身。不能用一个布尔值替代全部来源。
- 行动公式保留发射时快照，命中倍率读取真实命中前护甲；树种则重新建立完整行动。两者含义不同，复用上一事件的最终伤害不能实现独立再行动。
- 法术周期和到期都使用控制器的逻辑时间；`call_deferred()` 用于等待场景节点建立后再启动测试，不承担战斗时序。暂停、倍速和显示帧率不会因此改变效果顺序。
