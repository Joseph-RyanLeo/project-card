## 学习交接

1. **流程：** 玩家在准备阶段对卡牌实例执行装备／贴纸／纹章操作，状态写到 `OwnedCard` 或 `SquadData`；战斗开始时 `BattleController` 从小队及显现槽建立战斗副本；战斗事件更新副本和账本；正常结束由 `BattleSettlementService` 提交持久变化，未完成战斗则用战前快照回滚。`CardView` 与 `StatusSlotLayer` 读取这些数据负责显示，显示刷新不应创建业务状态或消耗随机数。
2. **关键职责：** `OwnedCard` 存一张实际持有卡的实例 ID、成长、伤势／纹章槽、符文状态和耐久；`CardData` 是多张同名实例共享的定义。`SquadData` 管小队成员、装备引用和位置。`BattleController` 管确定性战斗时间、状态副本及效果事件；`BattleSettlementService` 负责一次性提交；`main.gd` 连接主界面交互、准备和存档；`CardView`／`StatusSlotLayer` 只管卡面与槽位显示。
3. **GDScript 提示：** `OwnedCard`、`CardData` 都是 `Resource`，赋值往往是在传引用；修改共享定义会让同名卡互相影响，所以实例变化写入 `OwnedCard`。`Array[Dictionary]` 是带元素类型的数组，槽位用字典表达不同状态字段；`.duplicate(true)` 用于深拷贝嵌套容器，避免快照与运行状态共享可变子字典。`BattleController` 的显示信号／事件与账本分开，能让未结束战斗整体回滚。
4. **低风险练习：** 阶段交接时，可把 `CardView` 的 `hover_effect_delay_seconds` 从当前值临时增加 `0.05` 秒，运行检视／悬停回归并目测提示延迟，再还原改动。它只改变显示等待时间，不影响卡牌数据或战斗随机序列。验收时由开发者亲自完成并说明验证过程；练习尚未执行，不表示学习验收已通过。
