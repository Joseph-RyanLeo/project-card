# Project Card Demo Scope

本文记录 Project Card 第一个可玩 demo 的范围。目标不是完成全部规则，而是尽快验证“随从卡 + 叠卡 + 牌型 + 自动战斗”的核心体验。

## 工程位置

- Godot 工程直接放在 `Project Card/` 根目录。
- 当前目标 Godot 版本为 4.7。

## Demo v0.1 目标

玩家可以在准备阶段拖拽随从卡，把随从卡放到棋盘并进行水平堆叠。堆叠后形成小队，小队根据可见元素符文识别牌型。点击开始战斗后，玩家小队与固定敌方小队自动行动，直到一方全灭并进入结算。

## 本阶段只做

- 随从卡。
- 玩家两排棋盘。
- 基础收藏册。
- 固定测试卡组。
- 固定敌方阵容。
- 最多 3 张随从卡堆叠。
- 牌型识别：
  - 五条
  - 四条
  - 葫芦
  - 同花两对
  - 两对
  - 三条
  - 对子
  - 顺子
  - 混乱
- 自动战斗。
- 胜负结算后恢复战前四排卡堆，在压暗卡面上显示实际伤害、承伤、治疗、护甲和阵亡标识，再由玩家返回准备阶段。

## 本阶段暂不做

- 物品卡。
- 法术卡。
- 资源卡。
- 商店。
- 迷宫流程。
- Boss 流程。
- 伤势。
- 强化贴纸。
- 同花。
- 飞书表格同步。

## 已确认规则

- 受击优先级数值越大，越容易成为攻击目标。
- demo 优先体现叠卡特性。
- 同花可以先不进入 v0.1。
- 玩家棋盘为两排，每排横向容量暂定为 21 个战场单元。
- Demo v0.1 中随从卡固定拥有 3 个元素符文槽位。
- 单卡小队占 3 个战场单元；两张或三张随从叠卡后按可见符文数量换算占位。
- 三卡小队不再接受外部随从卡；五单元展开双卡只能从水平中间加入第三张形成 `1+3+1`，不能从两侧形成 `2+3+0`；小队内部抽卡后放回的重排与置顶不受此限制。
- 卡边错位 `10～40` 像素吸附到 30 像素紧密布局，错位 `>40～70` 像素吸附到 60 像素展开布局，范围外不建立新的叠卡意图；已吸附目标时允许连续穿过小于 10 像素的中心区，四单元紧密双卡可加入第三张成为五单元小队，三卡层级会自动保证每张卡至少露出一段。
- 单卡拖动预判上场或叠卡时会保留稳定的总让位预算；上场虚影与叠卡虚影的横向增量都包含在预算内，虚影改叠左/右目标时整体让位宽度不叠加，确认或取消后才恢复真实居中布局。
- 独立上场虚影会随当前插入边界在最左、小队间隙和最右之间移动；切换为叠卡时保留原让位位置，确保预览与最终提交索引一致。
- 基础受击优先级由行动方式决定：近战 4、远程 2、法术 3、治疗 1、防御 5。

## 推荐实现顺序

1. 建立主场景与阶段切换。
2. 定义随从卡数据结构。
3. 制作卡牌 UI。
4. 新增多张测试随从卡与基础收藏册。
5. 制作棋盘摆放区域。
6. 实现拖拽放置。
7. 实现随从卡堆叠与小队数据。
8. 实现可见符文与牌型识别。
9. 实现固定敌方阵容。
10. 实现自动战斗。
11. 实现结算与重开。
