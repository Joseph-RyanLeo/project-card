# 开包罕贵度接入（2026-10-27）

## 已确认规则

每张开包卡独立抽取两组外观，均为百分比：

| 卡面 | 概率 |
| --- | --- |
| 普通 | 40% |
| 银闪 | 25% |
| 金闪 | 15% |
| 彩闪 | 10% |
| 法线闪 | 5% |
| 碎闪 | 5% |

| 卡图 | 概率 |
| --- | --- |
| 普通 | 90% |
| 全息 | 5% |
| 超框 | 5% |

两维形成18种组合。例如金闪＋全息的概率为15%×5%＝0.75%。I～V品级、抽取卡池、数值和符文规则保持原样；本轮不新增外观保底。商店普通／定向包、免费稀有测试商店和迷宫奖励包都在生成真实单卡时抽外观；其他非卡包获得的卡仍为普通。

2026-10-27补充：两维外观现在参与局内出售加价，在原有最终卖价后追加，最高＋16金币；不改变以上抽取概率，也不代表局后积分。数值、统一入口及经济核算见[局内外观出售说明](CARD_APPEARANCE_SALE.md)。

## 从输入到画面

1. 原开包逻辑决定卡牌定义，再由收藏创建`OwnedCard`。
2. 卡包入口传入`pack_appearance=true`。实例从当前获得随机状态与实例ID派生外观随机源，各抽一次卡面、卡图；不推进卡池、行动、符文及槽位的随机流。
3. 卡面与卡图结果和金币、收藏、售出标记一起保存，再播放开包。存档失败沿用原事务恢复实例序号、金币、收藏和随机状态，重试得到相同结果。
4. 开包的前卡、后层卡边和再次检视复用`InspectionCardSurface`，将实例的两个字段交给同一材质控制器。揭晓／收起只展示，不再生成或重抽卡牌。

## 数据与脚本

- `scripts/data/card_appearance.gd`：两组枚举、百分比权重、稳定保存键和取景键映射。调整权重在`SURFACE_WEIGHTS`、`ART_WEIGHTS`中修改；每组须保持合计100。
- `scripts/data/owned_card.gd`：`surface_finish`、`art_finish`属于单卡实例，内存快照包含两者。
- `scripts/data/owned_card_collection.gd`：卡包创建入口只抽一次；伴随生成的衍生卡不自动获得开包外观。
- `scripts/data/run_save_service.gd`：JSON保存为`surface_finish: "gold"`、`art_finish: "holographic"`等稳定键；读取缺省字段为普通，未知键拒绝读取。
- `scripts/ui/card_view.gd`：从实例选择取景位置，静态卡面复用人物材质、超框层和图标光影；只在需要时创建控制器，不为收藏中的每张卡新增独立Viewport。
- `scripts/ui/inspection_card_surface.gd`：已有活动检视画布承载整卡扫光与碎闪。特殊外观采用4倍采样，倾斜、人物深度和图标光照使用同一平滑方向。
- `scripts/ui/card_finish_preview.gd`：调整器与正式展示共用双维度控制器。`surface_finish`控制扫光／法线／碎闪，`art_finish`控制普通／全息／超框；全息和法线可以同时生效，超框人物也可叠加法线。

卡图为全息／超框时优先使用该卡图已保存的取景；普通卡图按卡面选择位置。银／金／彩闪共用既有`foil`取景。调整器原有六项入口仍用于单项工艺调节，真实组合由实例配置；反光强度和外观权重不会写回共享卡牌定义。

## 初学者需要理解的写法

- `enum`是有名字的整数，便于代码和检查器选择；磁盘使用字符串键，避免选项顺序变化误读旧存档。
- `RandomNumberGenerator`是独立随机流。外观随机源由稳定状态派生，相同事务重试可重现；渲染函数不调用随机抽取。
- `load(...).new()`用于在卡牌就绪后载入控制器，避免`CardView`与持有它的控制器相互预载。
- 多层效果先合成，再交给整卡Shader统一变换；直接对各层分别旋转会破坏统一倾角与贴纸命中。

## 验证入口

- `tests/pack_card_appearance_test.gd`：逐一检查100个票位、5000张真实实例统计、18种组合、玩法随机流不变、快照与JSON读回、旧档缺省、坏档拒绝、正式小包保存失败回滚和成功落盘。
- `tests/pack_card_appearance_visual_test.gd`：正式CardView与InspectionCardSurface的18种组合GPU渲染、颜色、法线、超框、全息、取景和鼠标方向。输出`/private/tmp/project-card-pack-appearance-18.png`。
- `tests/pack_card_appearance_opening_test.gd`：继承既有开包输入验收，只陈列当前选中的真实生成卡包，检查实际鼠标购买、撕包、后层卡边、工具箱、刮符文、逐张收卡以及展示前已落盘的外观。旧`card_pack_opening_test.gd`在当前叠包布局中会命中另一包，使刮符文用例误用法术卡，未将该旧用例计入通过项。
- 既有`tests/card_finish_visual_test.gd`、`tests/d2_5_owned_card_snapshot_test.gd`检查材质与实例回归。

所有自动Godot进程须串行运行，并显式指定`--log-file /private/tmp/project-card-<用途>.log`；GUI画面验收不能用无窗口空渲染器代替。
