# D2-8 卡牌经济调整（2026-10-05）

本轮实施用户确认的同名降权、行动定向采购与三卡置换。权威规则已同步到 `GAMEPLAY_DESIGN.md` 和 `GAMEPLAY_RULE_DETAILS.md`；工作继续使用主目录、main分支，保留之前的修改。本轮未提交或导出新版本。

## 一、功能怎样从输入走到结果

### 同名降权

每次需要生成卡牌时，统计真实收藏中各定义的实例数量。部署、堆叠和装备不会让实例离开收藏，因此都计数；自动资源区的本关卡牌不属于收藏，不计数。

持有不足3张的定义权重100，达到3张后权重20。卡包先沿用原品级权重抽出品级，再在该品级内按上述权重选择种类。同一个包前面抽出的卡马上加进临时计数；持有两张后抽中第三张，本包下一抽便开始降权。

20%是相对种类权重，并非固定20%的中奖概率。若某个品级只有A、B两种卡，A已持有3张，A的概率是20／120＝1／6；若A、B都达到3张，两者仍各50%。售出或置换后数量降到2张，后续生成恢复权重100。

应用范围：普通与定向卡包、商店明暗单卡、随机随从事件、结算随机卡奖励、资源开采的随机装备／碎晶奖励、哨位的随机法术产出。保留各来源自己的候选范围、品级规则和IV持有去重；不改变自动资源、随机战斗目标或纹章掉落。

已经生成的商店报价不会因收藏数量变化重抽内容，买下不同商品后也不会重新洗其余商品。降权作用于下一次生成报价／奖励。

### 行动定向采购

商店右上角点击“定向采购”，再选近战、远程、法术、治疗、防御。每类一次生成1个小包、1张明单、1张暗单；无候选时该类没有商品。所有候选均来自本局开放的对应行动随从池。

小包3张、12金币，明单沿用品级价格，暗单显示所选行动、8金币。定向小包使用原行动图标3倍加代码绘制的像素包装轮廓，最近邻过滤保持像素边缘。右键可只读检视，左键购买走原有扣款、入库、包装动画和保存流程。

多行动且无均衡的卡获得后固定为采购方向，卡面与实际小队行动一致；均衡仍按部署排决定行动。普通商品和五种定向商品共用一次刷新，切换分类不抽随机数。存档保留真实报价、方向、售出状态和随机状态；旧商店报价读回不补抽，刷新后才生成新货源。

### 三卡置换

点击“置换”，将3张同品级的I、II或III级非衍生随从放进三个空槽；可以不同名。双卡／三卡小队成员必须先拆开。槽内保管原CardView节点，来源卡位为空，OwnedCard拥有权和战场数据在确认前保留。

槽内卡可单击携带或原生长按拖回收藏；收藏翻页时卡面留在置换槽，翻回来源页时重绑到该页的新空卡位。返回商品、离店、读档或Esc还原会归还暂存卡面。

点击“确认置换”后，从当前开放卡池抽一张高一级随从，免费。原三张实例、贴纸、伤势和成长消耗；装备原实例解除宿主绑定后留在收藏。新卡从自己的定义初始化符文、槽位等数据，不继承材料状态，并按新收藏卡显示绿点。

III→IV遵守现有IV持有去重：所有合法IV都持有时禁用确认，材料和随机数都不消耗。确认成功立即保存；写入失败恢复整个收藏、部署、装备、金币、实例序号、随机状态和槽内选择。成功清空三槽，重复确认不能再获得卡牌。

## 二、关键数据和脚本分别负责什么

- `data/demo2/ordinary_shop_config.json`：保存同名数量门槛、100／20权重、定向采购开关及置换材料数／最高品级／费用。小包数量与价格、明暗单价格沿用已有字段。
- `scripts/data/ordinary_shop_service.gd`：`count_owned_cards()`统计持有数；`card_name_weight()`取得种类权重；`draw_card_candidate()`负责加权种类抽取；`draw_card_pack()`保留品级抽取、保底和同包即时计数。`_append_action_procurement()`生成定向报价，存档校验检查方向与真实内容一致。
- `scripts/data/owned_card_collection.gd`、`owned_card.gd`：继续负责唯一实例增删与初始化。共享CardData不保存材料成长或采购选择；实例的`resolved_action_type`保存采购方向。
- `scripts/main.gd`：商店页切换、三个槽的输入检查、候选生成、确认事务、存档和失败恢复。`_shop_exchange_ids`只保存选择的实际实例ID，`_shop_exchange_slots`保存三个界面槽。`_capture_shop_card_transaction()`及对应恢复函数复用卖卡／撕卡的事务边界，并加入商店随机状态。
- `scripts/ui/card_service_slot.gd`：强化、原卡牌服务与置换共用。`show_card()`搬入实际卡面，`return_card()`归还；`rebind_collection_source()`在来源页重建后更新归还地址。收藏构建在暂存卡位置建立空容器，不复制第二个CardView。
- `scripts/ui/action_card_pack_art.gd`：用Control绘制小包，TextureRect展示对应原行动图标，不新增位图资源或依赖。
- `scripts/ui/card_view.gd`：行动图标及优先级使用实例确定的方向；战斗明确覆盖仍优先。
- `scripts/flow/short_maze_controller.gd`、`scripts/battle/battle_controller.gd`、`battle_hero_runtime.gd`：原奖励入口复用同一个权重算法。战斗持有字典的键继续用于IV去重，值改为数量，再计入本场已登记的奖励。

## 三、需要特别理解的GDScript写法

- `signal.connect(callback.bind(index))`：信号原先发送拖拽数据，bind在参数末尾附上槽编号。三个槽因此共用同一选择函数，不需要复制三份处理逻辑。
- `reparent()`：只移动显示节点的父节点，不复制资源、不转移OwnedCard拥有权。槽内展示的就是来源卡面，归还前记录来源父节点、位置、缩放和拖拽绑定。
- `queue_free()`：节点在帧末释放。翻页重建可能让旧来源容器进入释放队列，因此归还前必须检查容器有效且未排队删除；若来源页不在当前页，释放这张显示节点即可，拥有实例仍留在收藏，回到该页再正常创建卡面。
- 加权抽取：先算候选权重总和，在1到总和之间掷一次整数，再依次减权重；第一次减到0或以下的候选就是结果。这让20和100直接控制相对机会，不依赖循环重抽。
- 随机事务：先复制RandomNumberGenerator状态进行抽取，成功时提交新状态；保存失败时恢复旧状态。存档中的种子与状态沿用十进制字符串，避免JSON数字精度损失。
- `.duplicate(true)`用于复制嵌套状态容器，而共享卡牌资源和实际拥有实例由现有快照层按ID／引用恢复；不能将节点复制或资源副本误当成新的拥有卡牌。

## 手动试玩入口

1. 进入下一家普通商店或刷新当前商店，点击“定向采购”，切换五种行动，右键包图查看名称，再购买。
2. 点“置换”，拖三张同品级低级随从入槽，翻页后拖回一张，再补回，观察确认按钮条件。
3. 给其中一张材料装备物品并贴纹章，确认置换，检查新卡、装备回收藏、贴纸消耗与金币不变。
4. 重新读档核对结果；打开置换但不确认后离店，检查三张材料仍在。
