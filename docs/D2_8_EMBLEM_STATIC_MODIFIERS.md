# D2-8 纹章静态属性

## 生效范围

静态修正按纹章 ID 显式定义，不从悬停文案实时解析。每枚贴在有效槽位的实例各计一次；读取存档时仍由槽位重建，不写入 `permanent_growth`，刮下后只移除该枚纹章贡献。卡牌共享的 `CardData` 不会被修改。

| 纹章 | 已接入的静态属性 |
| --- | --- |
| 长剑 | 基础数值 +1 |
| 面包 | 基础生命 +2 |
| 改造 | 生命上限 -1、基础护甲 +2 |
| 盾牌Ⅰ | 基础护甲 +2 |
| 盾牌Ⅱ | 基础护甲 +4 |
| 盾牌Ⅲ | 基础护甲 +4 |
| 火腿面包 | 基础生命 +4 |
| 苹果派 | 基础生命 +3 |
| 烤面包 | 基础生命 +5 |
| 名剑 | 基础数值 +2 |
| 羽毛Ⅰ | 热诚 +2 |
| 羽毛Ⅱ | 热诚 +3 |
| 奶酪面包 | 基础生命 +4 |
| 三明治 | 基础生命 +5 |
| 树 | 基础生命 +5 |

卡牌原生行动数值仍由最左卡提供，原生生命与基础护甲仍由最右卡提供；永久成长也仍留在原来受成长的 `OwnedCard` 上。所有小队成员的显现、未遮挡纹章与伤势修正都合并到小队最终数值，每个合法槽位实例只计一次。小队卡面、检视预览与战斗统一读取 `SquadData` 汇总。

装备与日月星仍在小队汇总层加算：装备数值、生命、护甲在原有位置叠加，日月星沿用原属性路径。新纹章修正先并入来源卡基础属性，未改动已有装备或指示物加成。

生命项按当前 `CardData.max_health` 的生命上限处理。“改造”的源描述为“生命值-1”，本阶段将其接入现有生命属性字段；准备阶段属性改变仍沿用补满生命与护甲的既有重算规则。热诚仍以层数汇总，再走现有每层5%的行动冷却速度换算。初始基础护甲直接初始化战斗护甲，不记作战斗中获得护甲。

## 混合纹章与暂缓效果

混合描述中已明确的基础属性部分会生效：盾牌Ⅲ的基础护甲 +4、火腿面包的基础生命 +4、名剑的基础数值 +2、苹果派的基础生命 +3、奶酪面包的基础生命 +4、三明治的基础生命 +5、树的基础生命 +5。战斗特效状态见下方 D2-10；混合纹章不重复加算基础生命。

长剑、面包、改造、盾牌Ⅰ/Ⅱ及羽毛Ⅰ/Ⅱ的属性均按目录与当前规则接入。“强化+N”不转换成基础数值加成，而是写入战斗强化 modifier。元素贴纸和已接入的混沌奖励保持原逻辑。

## 实现路径

纹章目录按定义 ID 返回静态数值；`OwnedCard` 保存每个纹章／伤势实例和单卡永久成长；`SquadData` 遍历整个小队并按合法槽位遮挡筛选附加修正，再与原生属性来源、装备和指示物合算，最后统一截断。热诚进入现有冷却换算。这样基础属性来源没有被堆叠规则改写，实例附加效果也能跨卡影响小队，刮除与存档仍按原所属实例撤销或恢复。
