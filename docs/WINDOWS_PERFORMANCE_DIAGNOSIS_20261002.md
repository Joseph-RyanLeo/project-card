# Windows 实机卡顿诊断：导出符文资源读取失败

> 本文保留修复前实机证据；后续代码修复与回归结果见 [卡顿修复记录](PERFORMANCE_FIX_20261002.md)。

## 结论

主要缺陷已确认在 `scripts/ui/rune_reveal_cover_style.gd:48`：用普通文件API读取导出资源的原始PNG。导出包中的Godot导入纹理存在，但磁盘原始PNG路径不存在。失败后 `_cover_alpha` 保持为空，下一个像素又重新尝试读取，因此每次卡面重建都会放大为大量失败的文件访问与错误日志。

这是一项导出资源使用错误。本轮只分析、保存证据和增加导出包回归入口，尚未修改生产代码或重新导出游戏。

## 确认的错误链路

实际引擎日志与stderr各有610995次相同图片读取失败，每次产生两条ERROR信息。两份文件分别122810989、125253975字节，合计约248MB；它们是同一批错误的两路输出，不将失败次数重复相加。

```text
ERROR: Error opening file 'assets/card_ui/rune_covers/rarity_i.png'.
ERROR: Failed to load image. Error 7
```

流程为：

1. 翻页、随从虚影、阶段切换等创建/刷新CardView。
2. 未揭晓的每个符文槽建立刮痕遮罩，`create_mask_image` 扫描23×23像素。
3. `_is_asset_pixel_opaque` 发现缓存为空，调用 `Image.load_from_file(ProjectSettings.globalize_path(...))`。
4. 在导出运行中，该路径变成普通磁盘路径 `assets/card_ui/rune_covers/rarity_i.png`，读取失败。
5. 函数返回false，缓存仍为空；下一个像素再次加载。一个完整扫描可以失败529次，三个未揭晓槽的一次重建可以失败1587次。

610995正好是529×1155，符合完整像素扫描反复失败的模式。这个数字也包含共用覆盖像素查询的其他扫描，不能当作精确的CardView重建次数。

工程内测试时原始PNG位于磁盘，缓存首次建立后可正常复用；因此之前Mac工程测量没有暴露导出运行的失败链路。它们仍能说明正常加载后的重复刷新成本，却不能代替导出包验证。

`state_sync_ms` 是同一采样间隔内多次同步回调的累计耗时。它不等于GPU耗时，也不能与包含它的 `battle_advance_ms` 相加。开始附近同一记录的 `frame_ms` 仅138.870ms，明显不足以代表4779ms同步阻塞；引擎delta不能当作独立墙钟时间，P95为16.667ms也不能证明没有偶发长卡顿。

本次采集重定向了stderr并指定引擎日志，可能增加报错写入成本。反复读取失败本身来自游戏实现，修复后仍须在同一Windows设备复测正常运行与诊断运行，比较体感和日志。

## 如何对应伙伴反馈

- 翻收藏：会创建多组带未揭晓符文的卡面与翻页快照，共同触发失败扫描。关联明确。
- 开始/结束战斗：四排卡面的清理与恢复集中在阶段切换，伴随同一缺陷；初始化附近已有4.78秒同步记录。结束总耗时的精确数值需要补操作计时。
- 拖动随从：随从产生叠放虚影和邻近目标快照，带符文遮罩；装备预览没有相同的遮罩创建负担。代码与本机正常资源测量都支持这条差异，但这份Windows原生拖动耗时漏计，不能给出实机精确倍数。
- 纯卡包悬停：卡包本身的悬停代码不查询符文覆盖像素。商店中的可见随从单卡、进入/离开时其他刷新会触发错误，纯包悬停仍需修复后单测，避免把混合操作误判为包动画问题。

## 修复与复测顺序

1. 覆盖像素来源改为现有缓存的 `Texture2D.get_image()`，按需解压图像；读取尺寸与有效像素数量后一次建立缓存，移除逐像素尝试磁盘读取的路径。
2. 用真实导出资源包验收：素材23×23、有效覆盖409像素、中心可刮、连续查询不重新加载；检视刮擦、70%揭晓、保存/继续游戏都要覆盖。
3. 减少同一事务中的重复CardView刷新和遮罩/材质重建；保留现有未揭晓信息隔离。
4. 给原生拖动补计时，增加翻页、开店/离店、战斗开始/结算操作标记和独立时钟间隔，再用这份71–72张存档与同一硬件回测。
5. 错误归零后评估纯卡包悬停是否还有绘制负担；当前数据不足以要求更换硬件或将问题归于显卡驱动。

## 实现学习

整体流程的错误发生在“卡面需要像素数据→读取素材→缓存透明度”这一步，不在自动战斗规则。

关键脚本/数据是 `RuneRevealCoverStyle` 的 `COVER_TEXTURE_PATHS`、23像素 `SIZE` 和静态 `_cover_alpha`；`CardView._refresh_runes` 创建遮罩，OwnedCard的刮痕命中与统计也共用覆盖像素查询。

`ProjectSettings.globalize_path` 只转换为磁盘路径，不读取Godot导入资源；导出资源按 `.ctex` 等导入格式组织，应由 `load`/ResourceLoader获取Texture2D，再以 `get_image()` 取算法需要的像素。资源路径与普通文件路径的区别，是这次编辑器运行正常、导出运行失败的关键。
