# 英雄等级经验面板

## 从输入到显示

战斗或事件仍通过`HeroProgressState.grant_experience()`记入累计经验，再按正式阈值计算等级。HUD刷新时只读取状态：上排10盏等级灯点亮当前等级数，下排18盏经验灯依次显示已得、未得和本级不涉及三种状态。满级后18盏经验灯全部点亮，额外经验继续累计。

保留L级升下一级需要2L经验：累计9经验是3级、本级3/6，对应3个亮经验灯、3个暗灯、12个空心灯。累计89经验是9级17/18，累计90经验达到10级。未修改现有奖励、阈值、存档或当前第一层限制。

本轮底板最初按下半视角屏幕位置(1085,381)、视角原点(-1,368)确定世界位置(1084,749)。随后用户要求上下视角实际移动距离改为364像素，下半原点Y改为367，底板世界位置保持不动，所以屏幕位置变为(1085,382)。切换视角仅移动世界父节点，英雄面板不单独钉在屏幕上；详见[视角移动与回弹](CAMERA_MOVEMENT_20261019.md)。

## 脚本与素材职责

- `scripts/data/hero_progress_state.gd`：继续保存唯一的累计经验与等级；新增`get_current_level_experience()`，以累计经验减当前等级起点；`get_next_level_experience_required()`读取相邻阈值之差，满级返回0。
- `scripts/ui/maze_run_hud.gd`：建立185×357底板、原有圆柱装饰、至高天灰圈白底占位、实际姓名与四个天赋位。灯条相对底板(16,197)，天赋位分别(47,235)、(103,235)、(47,281)、(103,281)。天赋效果提示与选中颜色沿用原实现。
- `scripts/ui/hero_progress_lamps.gd`：独立小型`Control`负责绘制和悬停说明；只缓存显示数据，不保存第二份进度，不改变升级。
- `assets/ui/hero_progress_20261019/`：提供的底板和四张灯图逐字节复制，两个圆形占位沿用此前Aseprite导出。原图尺寸和SHA256记录在`素材来源.json`。

## Godot写法说明

`_draw()`是Godot自定义绘制回调；数据更新后调用`queue_redraw()`，引擎再绘制。几十个小灯使用同一节点即可，不需要为每个灯创建独立控件。

`draw_texture_rect_region()`先接收纹理，再接收目标矩形和来源矩形。本次来源、目标矩形尺寸完全相同，因此是裁切／拼接原像素，不是缩放。原经验底槽20格、宽153；删除最后两格14像素后，把原右端7像素圆角接回，得到139像素的18格经验条；左右各缩进7像素，与上方153像素等级条居中。

子节点的`position`相对父节点，`global_position`还包含世界视角位移。这次底板坐标按下半视角换算一次，其内部所有装饰、灯条和天赋位都采用相对底板坐标，防止叠加视角偏移。
