# 卡牌交互与收藏检视修正

2026-11-02，按本轮五张截图的八项反馈，在主目录 main 顺序修改。保留已有未提交工作，未提交／推送 Git，未升级引擎或增加依赖。本文补充并取代旧收藏说明中对应的详情按钮与动画行为。

## 功能如何运作

1. 点击携带卡牌时，预览进入现有最高携带层。拿起时清掉旧悬停，携带／原生拖拽期间统一阻止其他卡牌的检视倾斜与效果提示；放下后恢复普通指向。
2. 啤酒杯名称移除不受当前字体支持的啤酒 emoji。装备热诚为正才加 `+`，负数保留 `-`，零只显示 `0`，卡面和收藏详情一致。
3. 碎闪接入静止卡面的已有工艺覆盖层，收藏与战场不指向也能显示；战场卡内移动继续把指向位置传给碎闪材质。进入合成检视后关闭静止覆盖，避免同一工艺重复绘制。
4. 指向堆叠卡后，小队模式计时到达只切换提起／整队反馈；鼠标仍在目标卡上时，保留其效果提示。真正移开、拿起或暂停时才收起。
5. 收藏右键从当前卡位与倾斜角度过渡到逻辑 4 倍，时长 0.28 秒；随后右侧信息按行错开出现，每行从 0.94 倍恢复原尺寸、用 0.13 秒显现，相邻间隔 0.035 秒。背景使用透明度 0.68 的变暗蒙版，详情区另有底板确保文字可读。动画途中也能右键／Esc关闭。
6. 选中金光成为卡面本地坐标中的子节点；悬停时复制到共享合成卡面，因此金光与卡牌经过同一透视，原位不留平面的金框。
7. 收藏右上角增加 I—V 品级、随从行动方式与卡名／效果搜索，三者组合生效。筛选隐藏卡牌不会取消已选结果；无匹配时明确提示。沿用逻辑 1 倍静止卡、直接左键选择与连续滚轮浏览。
8. 右侧改为“卡牌详情 / 积分构成”两页，正文复用项目中文黑体。积分页复用正式计分器，列出品级、卡面、卡图、贴纸、符文和单卡牌型，以及本局倍率后的分值；查看不会发分。整局仍只在总基础分乘倍率后统一向下取整。原“卡面 / 效果”只是翻动左侧底栏，弹窗模式下尤其没有明显变化，现已从此详情界面移除，效果直接列在详情正文中。

## 核心脚本与数据

- `scripts/main.gd`：沿用 `_click_carry_layer` 承载手持预览，加入 `card_interaction_hosts` 组提供统一携带状态。
- `scripts/ui/card_effect_popup.gd` 与 `card_view.gd`：公共携带状态检查、提示延时、卡面输入与热诚格式。`clear_pointer_hover_feedback(preserve_effect)`区分清除抬起反馈和清除效果提示。
- `scripts/ui/squad_view.gd`：切换小队模式时只为当前 `_hovered_card` 保留提示，其他成员照常清理。
- `scripts/ui/card_finish_preview.gd` 与 `shaders/card_rest_flash.gdshader`：复用原静止工艺覆盖层与共享 `fractured_finish()`，不为每张静止卡新增 SubViewport。
- `scripts/ui/card_selection_halo.gd`：绘制卡边金光；原卡与共享倾斜副本读取同一个时钟，交接不重置尾迹。未选中时停止每帧绘制。
- `scripts/ui/collection_candidate_card.gd` 与 `collection_card_hover.gd`：同步选择状态和金光副本，保留真实卡位输入；仅当前悬停卡借用一份高分辨率合成层。
- `scripts/ui/slot_hub.gd`：缓存候选卡位，只切换可见性实现筛选；`_inspect()`组织放大、蒙版、页签与详情，`_score_text()`调用正式 `RunScoreService.card_score()`。动画参数集中在文件顶部，均有中文注释。
- 候选与已选结果仍来自 `progress.run.candidates`／`selection`，本轮没有另建一套收藏数据或改动入账规则。

## 初学者需要理解的写法

`add_to_group()`让提示框与卡面查询当前主场景是否正在携带，避免各自维护一份容易不同步的“正在拖拽”变量。组中主场景提供状态，显示脚本只读取。

子节点使用父卡面的本地坐标。把金光放入卡面的合成画布后，现有透视着色器自然同时变换卡和金光；不需要另外计算一套倾斜金框。

`Tween`负责在一段时间内平滑修改倍率和透明度；通过节点的 `create_tween()`创建后会绑定该节点。关闭详情释放节点时，其动画随之停止，避免关闭后又迟到弹出文字。正文行的位置与自动换行高度始终由 VBoxContainer 管理，动画不再读写行位置。

筛选控件的 `item_selected`／`text_changed` 信号只触发显示刷新，不触发收藏保存。点击卡牌仍沿用原选择事务，保存成功才更新选中状态；被筛选隐藏的已选卡仍保留在 `selection` 中。

## 后续修正：详情文字叠在第一行

用户随后在火枪手详情截图中发现叠行。初版 `_reveal_detail_rows()`只等待一次 `process_frame` 就记录行位置，不能保证容器已经完成延迟排版；一旦记录到所有行的初始零位置，Tween就会把已经排好的各行重新拉回第一行。上一轮测试检查了透明度先后，却没有检查行间几何关系，因此未捕获此问题。

修正后删除位置读取、位置偏移和位置 Tween；保留逐行错开，仅动画缩放与透明度。`DETAILS_ROW_START_SCALE`控制轻微弹出尺寸，最终严格恢复1倍；容器始终独占排版，不依赖等待多少帧来猜测布局时机。

新增 `tests/collection_detail_layout_test.gd` 使用真实收藏路由、火枪手、长来源和累计战绩，在720p与2K下逐帧检查动画中、动画结束后的行边界不重叠、换行高度、滚动至末行、原尺寸恢复、真实点击积分页和动画未结束时反复切页。30 FPS真实GPU运行34项通过，原收藏检视38项通过；本次共72项GPU断言通过，另有34项无窗口验证通过，未重复计入。测试只使用隔离临时档，未运行全量。

## 后续调整：黑体正文与取消检视动画

按用户反馈，两页正文的每个 Label 显式使用现有 `CardTextDisplaySettings.readable_font()`，即项目内 Noto Sans SC 黑体。字号仍为20，保留自动换行、滚动和逐行显现；同日后续反馈又将右侧标题、副标题及页签统一为黑体，卡面字体沿用原设置，见[七项反馈修正](CARD_UI_FOLLOWUP_20261102.md)。字体覆盖属于单个 Control 的主题覆盖，不会自动传给子节点，因此在实际文字控件上分别设置。

右键、Esc和关闭按钮统一进入 `close_inspection()`：先停止尚未结束的放大Tween和指向更新，再以0.22秒把卡面回正、缩回最初卡位，同时使整个检视层（详情、底板和蒙版）渐隐，最后释放节点。`INSPECTION_CLOSE_SECONDS`可调整退出时长，目标位置和倍率在打开时记录在当前覆盖层元数据中；这只是显示状态，不写入存档。

`_inspection_tween`保存当前进／出动画，用来在放大途中取消时停止原Tween，避免旧回调迟到创建详情。关闭过程中仍保留 `_inspection`并标记`closing`，所以显示壳继续消费Esc，覆盖层继续拦截输入，动画结束后才归还收藏界面。内部更换检视或筛选清理使用 `close_inspection(false)`立即释放，不留下两个覆盖层互相干扰。
