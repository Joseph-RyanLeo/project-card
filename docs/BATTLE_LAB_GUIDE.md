# 战斗实验室使用说明

战斗实验室是阶段 8 之后的开发者调试入口。它不维护独立战斗规则，而是把编辑好的阵容转换成正式 `SquadData`，交给正式 `BattleController` 结算。

## 打开方式

1. 进入收藏页面。
2. 点击右下角“战斗实验室”。
3. 点击左上角“返回主界面”可回到原收藏与战场状态。

实验室默认只展开中央战场。顶部“我方配置”“敌方配置”“日志与轨迹”分别控制左侧、右侧和底部抽屉；三个抽屉互不排斥，需要对照时可以同时打开。

## 配置一场战斗

敌我双方各有四个小队槽。每个槽可以设置：

- 是否启用、小队名称、前后排和排内位置。
- 近战、远程、法术、治疗或防御行动方式。
- 基础行动数值、冷却、生命和初始护甲。
- 一张D2-3效果测试卡；它会绑定到这个小队的正式战斗状态。
- 最多五枚从左到右的可见符文；中间选择“无”时会压缩为空槽。

实验室会把 0～3 枚符文生成单卡小队、4 枚生成紧密双卡、5 枚生成展开双卡，使正式 `SquadData.get_visible_runes()` 得到与编辑器完全相同的序列。中间四排会在编辑时立即以100%原始尺寸显示正式卡面，不需要先开始战斗；左右配置不再永久占宽，而是覆盖在战场上方的临时抽屉。单卡、紧密双卡和展开双卡仍分别保持正式 `99 / 129 / 159` 的宽度比例。配置抽屉下方同步显示识别到的牌型和实际卡牌数量。

实验室的冷却输入上限为99秒，用来直接测试最新版“实际行动间隔”边界。正式卡牌资源的基础冷却仍遵守0.5～9.9秒限制；99秒只通过实验室 formation 的运行时覆盖进入战斗，不会污染正式卡牌数据。

内置预设包括 `3光＋2水`、`2木＋2火`、`五火治疗`、`五水边界` 和 `五光目标不足`。预设适合快速检查分层、跨排、持续结算、邻接边界和合法目标不足。

## D2-3效果测试卡

每个小队的“测试效果”下拉框提供八张固定测试卡。它们不是另一套简化规则，而是生成正式 `BattleEffectDefinition` 并登记到同一个 `BattleEffectRuntime`：

| 测试卡 | 触发器 | 主要检查内容 |
|---|---|---|
| 战吼·热诚 | 战吼 | 自身热诚、固定秒数与到期移除 |
| 持续·重甲迟缓 | 持续 | AND条件、护甲条件失效与恢复 |
| 定时·整备护甲 | 战斗到3秒 | 整数逻辑时刻与瞬时加甲 |
| 战吼·蓄势 | 战吼 | 强化保存到下一次普通行动后消费 |
| 友军行动·刷新热诚 | 其他友军行动后 | 重复触发只刷新持续时间、不加层 |
| 战吼·随机鼓舞 | 战吼 | 固定种子的稳定随机友军目标 |
| 持续·同名旗帜 | 持续 | 同名不叠加、最早来源与来源退场接替 |
| 友军行动·封顶战歌 | 其他友军行动后 | 相加叠层与本效果6层上限 |

“友军行动”测试卡至少需要两个同阵营小队；“同名旗帜”应给两个小队都选择同一测试卡，才能观察最早来源生效和接替。配置预览悬停会显示效果说明；战斗开始后悬停会显示活动D2-3实例数、热诚与强化。

## 播放与观察

- “开始”和“重置同种子”使用当前固定种子重新生成状态。
- “暂停/继续”控制连续播放。
- “单步批次”推进下一个同时行动批次；打开“日志与轨迹”底部抽屉后，“分层轨迹”会同时显示D2-3效果的条件、选目标、应用、叠加和结束，以及原有基础层、主元素层和副元素层。
- 实验室复用正式战斗的弹道、行动抬升、元素颜色、命中脉冲与火焰持续命中闪烁；弹道到达后才结算数值。
- 四排实时卡堆在开始前显示配置卡面，开始后在同一比例卡面上覆盖当前生命、护甲、冷却和运行时行动值；强化会直接增加卡面行动值，消费后再回落。所有这些数字都以约0.24秒的先快后慢跳数动画抵达新值；悬停卡堆可查看精确值、四路小数余量、持续状态、Buff 与逻辑横向范围。
- “结构化日志”复用正式日志数据；带下划线的完整结果短语可悬停查看公式。

## 保存、断言与批量测试

“保存配置”把当前阵容、随机种子、速度、批次上限和预期结果写入 `user://battle_lab_scenario.json`；“载入配置”恢复同一份场景。

“运行并校验”会快速运行到战斗结束或批次上限，并检查：

- 实际胜负是否符合可选的预期结果。
- 生命与护甲是否为有限数值。
- 护甲是否保持在 `0～999`。
- 生命是否没有超过最大生命。
- 战斗是否在设定批次上限内结束。

“批量组合”固定遍历 `5 种行动方式 × 5 种元素 × 2～5 枚元素`，共 100 个场景。它适合快速发现新规则对其他行动方式或元素档位造成的回归，但不能替代 `tests/` 中针对目标选择和精确数值的专项断言。

## 推荐测试流程

1. 先用实验室预设或自定义配置复现问题。
2. 固定随机种子，使用单步批次和分层轨迹定位规则层。
3. 将预期结果填入场景并运行单场校验。
4. 修改规则后运行 100 组合批量测试。
5. 最后把重要边界写成 `tests/` 中的无窗口自动化测试，作为长期回归保护。
