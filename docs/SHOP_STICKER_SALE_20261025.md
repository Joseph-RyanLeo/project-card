# 商店工具箱纹章出售

## 第一层：功能流程

进入商店服务页并切到下半视角，单独打开工具箱。把普通纹章或元素贴纸拖入右侧卡牌出售槽，也可单击携带后点槽位；刚拿起时原格立即显示32%透明度的虚影，放入出售槽后延续同一透明度，不再突然出现。槽内显示4倍原像素图案和价格，工具箱原格虚影不可重复抓取，库存和金币尚未变化。

在出售槽范围内松手，图案从实际松手位置平滑吸附到槽中央。吸附与归位统一在画布前景飞行，全程盖在出售框、工具箱及其他贴纸上方，连续移动而不沿4倍工具箱的原始像素步进；原图仍按最近邻采样，保留像素边缘。槽内图案可再次长按拖动或单击携带；抓起后槽内不留图案。拖回工具箱原格或其他合法空格即可取消待售，非法落点或右键取消点击携带则飞回原虚影位置，不扣库存、不改变金币。已占用的出售槽仍可接收另一枚纹章，旧纹章恢复原位交互。

确认“出售”后仅移除这一实例、增加对应金币并保存。成功后按钮变为“撤销”，返还同一实例及原格位并扣回本笔金币；原格被占用时保留重试机会。关闭工具箱、换入卡牌或另一枚贴纸取消未成交预览。读档保留成交结果，临时预览和撤销机会不跨读档。

| --- | --- |
| Ⅰ | 1金币 |

| Ⅴ | 4金币 |

普通纹章与元素贴纸使用同一价格表，伤势不可出售；Ⅳ级没有用户确认的价格，保持不可出售。上半视角、非商店和卡牌检视工具箱不开放此入口。

## 第二层：主要脚本和状态

- `data/demo2/ordinary_shop_config.json`的`sticker_sale.prices_by_rarity`保存唯一价格表，`OrdinaryShopService.sticker_sale_price()`读取定义中的品级，缺少配置返回不可出售。
- `Main._shop_service_sticker_id`仅保存待售实例ID；每次选择、成交重新查询真实库存及权威纹章定义，不信任拖拽数据带来的价格。卡牌和纹章共用原出售槽，选择新目标会归还旧卡或释放旧预览。
- `EmblemLibraryView._reserved_item_ids`只管理待售显示和输入，原库存格位未移除；`_sync_entry_state()`统一处理演出隐藏、待售虚影和可拖动状态，避免开包／合成改写待售状态。
- 出售槽复用`EmblemLibraryEntry`，不再用只显示图片的`TextureRect`。`drop_target`将落在图案上的新拖拽交给真实服务槽；`native_drag_finished`通知Main释放待售状态，点击携带则在`_finish_click_carry()`走同一归还入口。`_return_shop_service_sticker()`只清除选择并调用`animate_sticker_return()`，库存本身一直保留该实例。
- 原生拖拽和点击携带统一调用条目的`begin_carry()`／`end_carry()`：工具箱来源立即淡化图标并关闭其鼠标接收，结束时恢复；出售槽设置`keep_carry_ghost = false`，因此槽内拿起时继续完全隐藏。这里只改变显示，不提前预留为待售实例。
- `EmblemLibraryEntry.play_return_feedback()`统一创建`_return_visual`前景四边形，用`_return_tween`插值其顶点；到位后删除飞行图案并恢复库存／槽内图标。重新抓取、替换定义、隐藏条目、关闭工具箱禁用拖拽和离开场景树都会调用`_finish_return_feedback()`，避免旧图案残留。
- `ShopBoardView._sale_root`将原出售槽、环绕贴纸、按钮和金额组织为同一组。打开独立工具箱时重挂该组，并使用原服务底图的右侧区域作为正常亮度背景；关闭时恢复原父节点。
- `_execute_shop_sticker_sale()`和`_undo_shop_sticker_sale()`仅修改本枚库存与金币，保存失败恢复本次修改。复用`_shop_service_undo`的按钮和生命周期，不改变其他卡牌、贴纸或报价随机流。

## 第三层：需要理解的Godot写法

`reparent(parent, true)`换父节点时保留屏幕位置。出售组挂在工具箱遮罩之上，因此既保持正常亮度，也能接收原生拖拽；关闭时移回原服务页，无需复制一套按钮和交易逻辑。

`AtlasTexture`只引用原902×351服务底图中的右侧区域，不生成或改写图片。环绕贴纸在工具箱模式中仍高于卡面，但低于4096层的鼠标预览，避免拖动纹章被遮住。

库存按`instance_id`取回深复制状态，显示使用同一实例身份。选择不等于消耗，取消不需要重新发放物品；只有确认交易才调用现有库存移除／返还接口。

`get_global_transform_with_canvas()`把不同父节点下的坐标换到同一画布；`affine_inverse()`再换回目标局部坐标。工具箱和出售槽有不同的父节点与缩放，不能直接相减局部位置。起点使用实际拖拽预览中心，终点为原图标四角的画布位置。

`Polygon2D.polygon`保存四角坐标，Tween直接插值这些顶点，做法与卡牌粘贴动画一致。上一版移动4倍父节点内的`Control.position`，会放大控件位置取整产生的步进；现在动画直接挂到当前`Viewport`，使用独立的最高绘制层级，不继承工具箱缩放、裁切或贴纸间的绘制顺序。归还工具箱时原图标继续作为32%虚影，前景图案以正常亮度飞回；到位后才删除前景图案并恢复原图标。出售槽自身的入槽动画仍隐藏槽内图案，来源虚影继续留在工具箱。

Godot会把`NOTIFICATION_DRAG_END`通知给所有节点，因此条目只在自己发起原生拖拽时恢复显示和发送结束信号；否则其他隐藏条目可能被无关拖拽错误显示出来。

`self_modulate`只改变图标自身的颜色／透明度，`modulate`会影响整个节点及其子节点。拿起时临时把图标的`self_modulate.a`设为0.32；入槽后的待售状态仍由库存条目的`modulate.a`管理。结束携带恢复前者为1，后者维持0.32，最终透明度相乘后仍为0.32。归位动画再由`play_return_feedback()`保持图标虚影，到位后的`_finish_return_feedback()`才恢复前者为1。卡牌同类处理见[归位虚影说明](RETURN_ORIGIN_GHOST_20261025.md)。
