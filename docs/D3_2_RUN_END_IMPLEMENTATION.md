## 1. 整体流程

正常战斗继续沿用原有战后整理。八天通关或失败保护耗尽后，“结束本局”将当前实际持有卡、正常耗尽法术、已收纳工具箱和金币冻结成结局。Esc新增“放弃本局…”：首次点击只弹确认，确认后直接按当前事件／战斗状态提交，不要求结束该事件。

整局结束时，先计算明细、冻结候选，再把积分余额、唯一凭证、结局、明细、候选和`summary`阶段放进同一档原JSON，一次保存成功才切换总结。积分自动入账，总结没有领取按钮。原子写入失败时恢复动作前内存、保留原磁盘文件，可再次结束；不会留下已扣耐久但未入账等半份状态。

页面顺序为：

```text
active 本局 → summary 总结（已入账） → selection 本次选卡
→ preview 集合预览 → 最终确认 → hub 档内大厅 → 手动新局
                              ↑ 返回选卡可继续调整
```

普通保存退出和崩溃不走结束入口。战斗中普通保存仍使用战前快照；确认放弃则正式提交本场已经产生的成长、消耗、奖励、发现和战绩，不补发尚未完成战斗的固定金币／经验，不把当天算成完成，也不加剩余保护倍率。

进入第一层第3天即可按放弃规则计分／选卡。前两天放弃为0积分、0候选，但已实际获得内容的发现照常提交。0张仍进入集合页，显示“本次未选择卡牌”，最终确认后才能开下一局。

## 2. 核心脚本、数据和函数

- `scripts/data/run_score_service.gd`：纯读取计分。使用品级、卡面／卡图积分表；纹章读取正式目录的真实品级，宝石叠加既有100分效果；伤势每枚5；覆盖或揭晓符文同槽只算3；单卡复用既有覆盖后元素与万能贴纸判型。逐卡保存六项组成和总分，工具箱逐枚保存；资源计分、衍生排除。
- `scripts/data/profile_progress.gd`：原`profile.points`继续作为唯一钱包；`receipts["run_end:" + run.id]`去重。`run.summary`保存结局与完整明细，`run.candidates`保存只读完整单卡，`run.selection`保存候选、固定位置、被换旧卡身份及二次确认。缺少总结字段的D3-1档只补空值，不追算旧分。新总结必须与凭证、逐项合计和倍率吻合，损坏数据拒绝恢复。
- `scripts/main.gd::finish_maze_run()`：结束事务入口。复用迷宫已有捕获／回退及`save_run_to_path()`，战斗中放弃调用同一个单场提交服务但跳过迷宫胜负奖励和日推进。保存成功才通知显示壳切换阶段。
- `scripts/flow/short_maze_controller.gd::continue_after_battle()`：在真实终局战后接入结束事务，普通天继续原来的跨日流程。
- `scripts/ui/game_display.gd`：按阶段恢复，轻量总结／收藏无需预建Main；选择变化与页面变化都保存，失败回退。未最终确认收藏时`start_new_slot_run()`拒绝新局。
- `scripts/ui/slot_hub.gd`：复用像素背景、精细黑体、按钮和真实CardView，提供默认总览、两列图片滚动明细、每行5张滚轮浏览候选、只读检视、新卡与3个旧位按逻辑2倍并排比较、替换二次确认及集合页。小卡左键直接选择／取消，右键打开左侧4倍大卡与右侧详情／计分两页；效果直接展示，不再使用翻面按钮。无刮刀、贴纸编辑或拖拽修改入口，长战绩可滚动。

同种收藏从左到右填空，最多3位。满位时点旧位下方“替换此位…”，第二次确认明确的新卡、旧卡外观与获得时间，才记录计划。预览期间旧卡保留，最后一次确认保存成功后才统一加入／换出；法术恢复全新次数，其余状态、原获得时间与战绩保留。

## 3. 单卡战绩的提交边界

`BattleSquadState`在真实伤害、治疗和护甲生效入口发出统计信号，`BattleController.owned_card_statistics`只暂存本场值。效果数值没有改变，过量治疗不计；队长记录小队事件，其余成员不重复累计。法术事件携带自身实例身份，内容召唤物携带原召唤源身份。

`get_owned_card_statistics()`汇总参战、首次阵亡和实际金币／开采账本；每场参战最多1，复活与再次死亡不再追加阵亡。`BattleSettlementService.settle()`在恢复战前状态后、移除耗尽法术前累加到`OwnedCard.lifetime_stats`，所以移除回调冻结的耗尽法术也保留本场战绩。同场重复提交在journal检查处返回，不重复累加。战前回滚不保存本场未提交值。

银月、铁壁和扭曲矿脉实际法术的直接事件补充来源身份，含延迟治疗。旧档无法还原的历史时间、来源和战绩仍留空，不倒推。

## 4. 初学者需要留意的写法

- `static func`用于计分：无需创建节点，也不依赖界面，方便用真实资源单独验证公式。
- 倍率存为整数十分位：1.2保存成12，最终用整数乘法再整除10，一次向下取整，避免浮点误差把整数边界少算1分。
- `duplicate(true)`会复制嵌套字典和数组，用于冻结候选与动作回退。仅复制顶层会让预览改选意外影响原数据。
- `StringName`用于运行时稳定身份，JSON使用普通字符串；读回的数字可为浮点数，因此校验先确认是有限整数，再转换，不能只按原始类型判断损坏。
- 信号只传本场实际事件，暂存统计不会直接改永久收藏。正式提交与普通退出走不同边界，是为了让SL回战前时不保留本场结果。
- CardView的定义与实例要分别绑定：`set_card_data()`决定画什么卡，`set_owned_card()`决定该实例的外观和状态；只传实例不会自动设置定义。
- 容器在布局帧确定按钮最终位置；自动鼠标测试必须等待布局。手工定位按钮还要显式设置实际尺寸，不能只调小`custom_minimum_size`后假定它自动缩小。
