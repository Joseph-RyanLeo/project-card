# 卡牌文字显示模式（2026-10-29）

Esc菜单的“卡牌文字”可切换“卡牌显示”与“弹窗显示”，默认前者。偏好单独保存在本机的 `user://card_text_display.cfg`，不属于三份游戏进度。

2026-10-30名称牌替换为83×13px，仍位于(0,4)；文字区域下移1px到(21,6)，继续保持61×9px，上下各留2px。

2026-10-30新增Esc“卡名字体调试”，可在固定61×9px区域中对比候选黑体与抗锯齿，观察1倍、4倍及像素放大镜。点击“应用到卡牌”可保存参数并返回游戏查看实际卡名，区域保持61×9px，游戏渲染方案不变；操作说明见 [卡名字体调试器](CARD_FONT_LAB.md)。

## 功能流程

卡牌显示沿用原来的像素字与悬停符文淡化。弹窗显示下，真实卡面负责鼠标命中，持续指向0.25秒后出现“卡名＋效果”弹窗；随从符文保持不透明，卡面不再叠加效果。正文读取当前OwnedCard与所在排的实际说明，包含前后排差异和实例变化，不另存一份描述。

短描述使用200逻辑像素的最小宽度；长描述以卡牌中心为轴向左右扩展，正文最多三行。优先放在卡面上方，顶部放不下改到下方，四周限制在窗口内。旧正文的手动换行在弹窗中重新排版，不通过省略第四行实现三行上限。极窄窗口容纳不下三行时才缩字。

弹窗使用深色标题区、浅色正文区；不添加参考图中的稀有度按钮。标题18号，正文16号，按窗口实际倍率设置字体尺寸。它位于根窗口的CanvasLayer，避开1280×720游戏画布放大文字的模糊。所有控件忽略鼠标，点击和拖拽继续交给真实卡面。

移出、按下鼠标、拖拽、打开Esc、切换显示模式、来源隐藏或释放时收起弹窗。商店明牌、服务卡位和资源／法术预览接入同一弹窗；商店暗牌不显示隐藏信息。右键大检视继续在侧边显示黑体卡名和效果，隐藏不再适用的卡面翻面按钮。

## 数据与脚本职责

- `scripts/ui/card_text_display_settings.gd`：唯一的模式、偏好读取／保存和字体资源；切换时通知现有卡面与菜单更新，新卡入树也读取相同设置。
- `scripts/ui/card_view.gd` 与 `scenes/ui/CardView.tscn`：鼠标延时、两种模式的底栏行为、61×9px名字区域；黑体卡名首选9号，按宽度缩字，不因字体行高的上下留白降到更小字号。
- `scripts/ui/card_effect_popup.gd`：一棵场景树共享一个弹窗。`source`指向文字来源，`anchor`指向定位控件；`_layout_content()`测量文字和扩宽，`_update_popup()`跟随卡面与窗口倍率。
- `scripts/ui/escape_pause_menu.gd`：显示模式入口与保存反馈。菜单扩大至360×668，保持在720p逻辑画布内。
- `scripts/ui/inspection_card_surface.gd`：黑体检视与商品卡面至少4倍采样；已经打开的表面在切换模式时同步提高精度。收藏悬停继续复用原有高清显示层。
- `assets/fonts/NotoSansSC-VF.ttf`：项目内中文黑体可变字体，配套原始许可证；不依赖系统字体安装情况。来源见字体目录README。

## 需要理解的Godot写法

`static var`属于脚本本身，所有卡牌共享一份模式；因此不需要为每张卡保存一个设置。`ConfigFile`是Godot原生配置文件，用来把显示偏好与玩法存档分开。

`CanvasLayer`把弹窗画到窗口前景，`MOUSE_FILTER_IGNORE`让可见弹窗不抢走卡牌的点击。内层卡牌坐标通过显示壳的变换转成窗口坐标，字体也用窗口像素排版。

`TextParagraph`负责按真实黑体字形测量断行。二分查找每次把候选宽度范围减半，找到可以放下三行的宽度；只有内容或窗口尺寸变化才重新测量，鼠标静止时不逐帧排版。

`FontVariation`选择可变字体的500字重；轴名通过TextServer的 `name_to_tag("weight")` 转换为OpenType标签，避免字符串键未生效而落到最细字重。黑体卡名保留9号，使用9px裁切区域居中字体行盒；高清悬停／检视保留曲线细节，静态原生卡面仍受1倍游戏画布及9px高度限制。

## 验证

专项 `tests/card_effect_popup_test.gd` 使用真实显示壳和鼠标输入，检查默认旧模式、切换同步、9号黑体、所有卡牌完整三行排版、左右扩宽、四角避让、来源清理、720p／1080p／2K重排与右键检视。额外运行既有卡面样式、服务拖拽和法术检视回归；不运行全量套件。

最终结果：弹窗无窗口与真实GPU各207项通过；旧卡面样式26项通过，真实GPU服务拖拽36项及法术检视29项通过。服务拖拽无窗口环境有一项原生拖动失败，真实窗口复核通过。既有Main资源UID路径回退警告仍会输出；无窗口渲染还会出现系统证书和资源清理日志，真实窗口三组专项未出现脚本错误。

实际画面预览由真实GPU窗口截图裁切，保存在 `docs/previews/card_text_display_20261029/`。预览长描述是测试专用文案，未修改正式民兵卡效果。

## 名称牌与文字区域的分工（2026-10-30）

卡面创建时，`CardView._apply_pixel_layout()`先按素材原生尺寸放置名称牌背景，再单独定位`NameClip`文字裁切区域。背景为83×13px、位置(0,4)，文字区域为61×9px、位置(21,6)；加高背景只增加留白，不增加字体的绘制分辨率。

`title_area_position`控制整块文字区的位置；字体调试器的上下偏移只作用于区内的`NameLabel`。`Texture2D.get_size()`读取素材本身的宽高，`clip_contents`裁掉越出9px区域的文字，因此背景尺寸和文字可用高度可以分别调整。
