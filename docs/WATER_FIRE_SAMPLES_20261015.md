# 水流与火焰样板（2026-10-15）

## 如何试用

游戏中按 Esc 打开开发菜单，进入“攻击特效调试器”；也可在 Godot 中运行 `scenes/tools/AttackEffectLab.tscn`。

- 选择“水·扩散”，点击“应用水流样板”。右侧在相邻卡位之间预览短水波：三条连续月牙弧带依次为亮色前缘、正蓝主体和透明度0.42的蓝色后缘。亮前缘和正蓝中层的默认厚度比此前增加约25%；后层基础厚度增加到此前约2.7倍，尾部边界以两层噪声连续起伏，三层内部仍保持纯色。波面默认宽112逻辑像素；两端随实际行进距离向后拉长，最多再延长波宽的0.60倍。可调“尾波流动速度”“尾波噪声密度”“尾缘起伏强度”。按钮保留当前播放时间、命中节奏长度、命中节奏柔化和变速强度，避免外观调整改变命中时刻。
- 选择“火·灼烧”，点击“当前恢复默认”可载入 160 像素默认高度。右侧显示真实卡面背后的宽底火焰，以及从卡外火团接入卡面少许的前景部分，循环模拟持续燃烧、每跳增强与终结爆燃。主焰尖向上收窄并弯折，低频噪声切出不规则侧焰，避免规则排列的多个焰尖与光滑椭圆。可调火焰高度、像素块大小、上升速度、焰尖噪声密度和焰尖摆动强度。这里的“预览持续时间”只控制演示；正式战斗由真实持续状态决定何时结束。
- 调节先改变草稿；“保存并应用”后正式战斗读取同一份配置。旧保存配置不自动覆盖；旧版九类 JSON 可导入，自动补上火焰默认参数，新导出文件版本为 2。

## 输入到显示的流程

水的扩散事件 → 共用弹道渲染器中的短水波网格 → 水流 Shader 分支 → 原有逻辑命中回调。短水波网格跟随波心横移，两端后拖量由已行进距离乘以“后拖强度”算出并封顶。Shader按圆弧后方的距离划分亮色、蓝色、半透明蓝色三层，没有内部随机色斑；前两层使用固定厚度，第三层的厚度叠加连续噪声，使其尾缘有不规则起伏，两端逐渐收窄。尾缘读取同一份可暂停的`effect_time`，不另建计时器。网格只沿行进方向扩容，前端保留透明余量，圆弧波心仍与真实命中同步；抵达后停在邻位消散，向左时整个网格转向。伤害、路径目标和原有命中延迟不变。

火的真实持续伤害／治疗／护甲状态 → `BattleFireVisual.sync_targets()` 按目标汇总 → 每个目标一个 `BattleFireVisual` → 同一个Shader用统一的`flame_shape()`绘制卡牌背后的宽底火焰与向卡内接入的一小部分。整体底形下宽上窄、底部留圆弧；两层向上平移的噪声侵蚀边界，生成一个主焰尖和不规则的侧焰、缺口。主焰尖末端收束噪声，避免撞到画布顶部后出现平切口；热区与亮芯限制在中下部，顶端以暗边、主体色为主。横向画布扩为原来的两倍，并在Shader中反向换算坐标，保持火团实际占位，防止侧边硬裁剪。前景与背景使用相同的位置、尺寸和像素网格，前景在卡外接触处生成向内尖形，按自身轮廓距离使用共用色板分层。前景先检查相邻的左右／底边卡外是否有火，再根据外侧火团厚度决定向内延伸深度，主体深度平滑收束到14逻辑像素以内，内侧轮廓叠加最多14逻辑像素的焰尖；顶部与没有外侧火团的位置保持透明。前景沿用外层暗边／主体／亮区的色板，按内侧轮廓重新分层，透明度为外侧火团的60%，允许半透明覆盖卡图和符文等元素；不会在卡外重复叠加透明度。高度、外扩和像素块都随卡牌显示倍率变化，火焰整体透明度 0.82。每跳时内部亮区增强、轮廓轻微膨胀，终结增强幅度更大。状态结束、目标死亡或返回准备阶段后清理。多份灼烧仍各自独立结算，只共用外观层。持续治疗和护甲共用相同火焰，每跳与五火终结都使卡面短促瞬白。

参考视频：[让火焰烧起来《五星地牢》开发日志04](https://www.bilibili.com/video/BV1vGaT6FEMB/)。本次通过网页播放器重新观看了底形与噪声塑形、叠加噪声、限制热区和亮芯高度、原始形状减缺口等片段（约 00:40、01:20、02:03、02:48）；借鉴其“底形＋上行噪声塑形＋分层色块”的思路独立实现，未使用视频素材或源码。

层级以本轮用户要求为准：背景火团在卡牌后，只有卡外实际露出火团的位置才向卡内延伸，沿用下层色板并按自身轮廓呈现三层颜色，内层单独降低透明度以透出卡面元素。正式背景 `z_index=-10`，前景 `z_index=1200`；调试器背景层10、卡面20、前景30。两者都用 `z_as_relative=false` 独立设置前景层级；前景仍是同一个火焰节点的子节点，自动继承暂停、显隐和释放，不另建一份灼烧状态。

火焰四档颜色取自用户 2026-10-15 提供参考图下方色板中央像素的中位数：暗边 `#6d4239`、主体 `#a75f49`、热区 `#d49c6b`、亮芯 `#ecd0a0`。均为纯色色块，火团透明度与出现／结束淡出单独控制。

## 文件与核心数据

- `scripts/battle/battle_attack_effect_profiles.gd`：共用配置，新增 `water_flow` 样式与 `fire_burn` 类型；沿用已有数值字段，不另建一套保存系统。
- `scripts/battle/battle_attack_trail_renderer.gd`、`shaders/battle_energy_beam.gdshader`：短水波与三档色块。`WATER_DEPTH_RATIO`与`WATER_MAX_STRETCH_RATIO`控制初始画布和两端后拖上限，`wave_stretch`保存实际后拖量，`wave_depth`同步绘制深度，`wave_opacity`控制消散。Shader的`WATER_FRONT_WIDTH`、`WATER_MIDDLE_WIDTH`、`WATER_REAR_WIDTH`分别控制三层基础厚度；`flow_speed`、`flow_frequency`、`warp_strength`复用为尾波速度、密度和起伏强度。
- `scripts/battle/battle_fire_visual.gd`、`shaders/battle_pixel_fire.gdshader`：火焰显示。`beam_height`控制高度，`pixel_size`控制色块大小，`pulse_strength`控制每跳增强，`foreground`选择前景接入遮罩，`card_rect`保存卡面在火焰画布中的矩形，脚本`FOREGROUND_DEPTH`控制主体向内深度，`FOREGROUND_TIP_DEPTH`控制额外炎尖长度，`FOREGROUND_OPACITY`控制内层透明度；Shader的`INWARD_RATIO`控制卡外厚度转换为卡内深度的比例。
- `scripts/main.gd`、`scripts/tools/battle_lab.gd`：各自的`_fire_burn_visuals`保存“目标 → 火焰节点”；统一调用`BattleFireVisual.play_event()`、`sync_targets()`与`clear_targets()`。显示层只读取`active_continuous_effects`和`elapsed_seconds`，不修改战斗状态。
- `scripts/tools/attack_effect_lab.gd`：编辑草稿与预览，直接复用正式渲染器和火焰节点。

## Godot 写法说明

`ShaderMaterial.set_shader_parameter()` 把脚本里的时间、尺寸和强度传给 GPU。Shader 的 `TIME` 不随游戏暂停，所以水流改用 Tween 提供的时间，火焰用战斗控制器的时间，保证暂停和倍速一致。

`Tween.tween_method()` 在一段时间里反复调用更新函数；用于预览而不创建第二套战斗逻辑。`get_global_rect()` 配合 `affine_inverse()` 把卡面真实矩形转换到特效层坐标，避免卡面中心缩放后火焰偏移。

Godot 默认把子节点的 `z_index` 加到父节点层级上。`z_as_relative = false` 只取消这项层级相加，不改变坐标、暂停或生命周期的继承；因此火焰可以继续由共用特效层管理，同时画在卡牌后方。Shader 中的 `field` 是轮廓判断值：大于等于 0 的像素显示，小于 0 的像素透明；噪声改变这个判断值，才能切出会运动的焰尖，而不只是给静止的椭圆内部换色。

## 内侧炎尖与半透明覆盖

按用户最新要求，在原有火团接触遮罩上增加细小炎尖。尖形由三角波加噪声轻微扰动，只影响内侧显示边界，取色仍由共用的`flame_shape()`产生；内外不另设两套颜色。主体最多伸入14逻辑像素，炎尖额外最多14像素，随真实卡牌倍率放大。内层透明度为外层的60%，正常显示时约0.492，允许稍微覆盖符文和卡图。

流程为“检测卡外火团接触→计算主体内缘→增加细炎尖→以原火团取色半透明覆盖”。Shader的`pow(triangle, 2.5)`把宽三角轮廓收窄成细尖，`smoothstep()`让卡外火团较薄的位置少长炎尖；不会从没有卡外火团的卡框位置单独生成火苗。透明SubViewport的RGB读回已乘Alpha，视觉测试需先除回Alpha再对照原始颜色，并单独检查内层透明度比例。

本轮最终验证：视觉检查19项、现有水火44项，共63项通过；验证包括内缘尖形、原始RGB取色一致、内层透明度比例、卡外接触、中央留白、边界完整，以及真实战斗暂停／倍速／清理。静态与动态预览已更新。

## 内层三色渐细焰尖

上一版只扩展遮罩，颜色仍读取完整背景火团的绝对坐标；新增尖形落入同一热区时，就会成为单色色块。本轮改为根据内侧轮廓距离计算三层颜色，沿用外层同一色板：暗边`#6d4239`、主体`#a75f49`、亮区`#d49c6b`。不再要求内外同坐标的RGB完全相同，因为内层拥有独立的可见边界；颜色一致指共用同一套原始色板。

主体向内范围仍为14逻辑像素，额外焰尖长度由8提高到14，尖形振幅提高并固定原有密度，使加长后依旧明显。内层透明度仍为外层60%，正常约0.492。卡外接触条件、顶部留白和外层火团均沿用原实现。

流程：卡外接触→计算向内主体与渐细尖形→测量到新内缘的距离→以共用`flame_color()`取三层颜色→半透明叠加。脚本`FOREGROUND_TIP_DEPTH`控制额外长度；Shader的`INNER_COLOR_DEPTH_RATIO`控制色层总厚度，`INNER_TIP_SPACING_RATIO`控制尖形密度。`rim_distance`通过斜率换算，避免斜面色层变成等粗条带；越靠近尖端，可容纳的亮区和主体越窄，最后收束为暗色尖端。

原生视觉测试改为核对共同色板、三层齐全、沿向内方向的亮区→主体→暗边顺序，以及原有半透明比例，不再使用已不符合新要求的“内外同坐标RGB相等”断言。

本轮最终验证：视觉检查22项、现有水火44项，共66项通过；无脚本或Shader错误。验证包括三色齐全、向尖端的色层顺序、加长尖形、固定半透明比例、卡外接触、边界完整及真实战斗暂停／倍速／清理。现有静态与动态预览已更新。

## 内层火舌统一向上升腾

用户确认焰尖需要与背景火焰一样向上扩散。此前按最近卡边的法线扩展尖形，左右两侧会向卡面中心横向伸出锯齿。本轮替换该几何：侧边火舌以屏幕Y轴为长轴，根部位于下方卡外火团接触处，越向上越窄，并略向卡内弯折；底部火舌保持根部横向位置，噪声沿Y向上流动，移除沿卡底横向滑动的时间相位。

流程为“找到卡外根部→沿Y向上拉出渐细火舌→与接触处主体合并→共用三色色板半透明显示”。`cycle`表示每段侧边火舌的上升周期，`root`保存其下方根部，`half_width`控制随高度收细，`rim_distance`用于三层取色。`INNER_RISE_SPEED_RATIO`调节内层升腾速度，并继续乘现有`flow_speed`与可暂停的`effect_time`。

Godot屏幕坐标Y越小越靠上；采样时使用`point.y + rise`，同一图案随时间会出现在更小的Y坐标，因此画面呈向上移动。`max(body_field, plume_field)`将主体与火舌轮廓合并，而不是新增一份战斗状态。三色、内层60%相对透明度及卡面中央留白维持原规则。

视觉验证改为检查火舌能在当前点下方的卡外火团扎根，并加入两帧原生画面的上移／下移重合度比较，避免只验证“时间参数变了”却没确认运动方向。

本轮最终验证：视觉检查23项、现有水火44项，共67项通过；无脚本或Shader错误。新增连续画面向上运动核对，三色色板、半透明、根部接触、边界完整与真实暂停／倍速／熄灭检查均通过。静态与动态预览已更新。

## 侧焰方案比较与连续翻卷（2026-10-16）

侧边固定间距的循环火舌会显出重复节奏，独立于背景生成的细长形状也容易像贴在卡边的细条。本轮删除这段周期与根部循环，改用外层火焰本身的连续轮廓。

| 策略 | 效果与取舍 |
|---|---|
| 复用外层火焰、向内翻卷（当前采用） | 接合与流动自然，共用外焰轮廓；对单根火舌的控制较少 |
| 少量固定根部的弯曲火舌 | 轮廓容易控制，但需细调数量、根部与生命周期 |
| 手绘逐帧侧焰 | 像素形状最可控，需要专门制作和维护素材 |

当前流程：卡外火团→向外侧取样并从下方向上翻卷→与接触处主体合并→三色渐细并半透明叠在卡面。`folded_point`表示前景像素对应的外焰位置；同一个`flame_shape()`提供连续轮廓和噪声，沿用外层向上流动的速度。`SIDE_FOLD_LIFT_RATIO`控制向上翻卷的斜度，现有`FOREGROUND_TIP_DEPTH`控制翻卷强度，归零时只保留接触主体。

越往卡面内深入，取样位置越往卡外移动，因此轮廓自然收束；`exp()`用来逐渐加快这种取样外移，避免最后突然裁成一条直边。三色仍取外层色板，前景仍为外层60%透明度。没有新增节点、保存参数或另一份灼烧状态，底部焰尖保持原实现。

旧的“整根火舌平移后重合度”测试依赖周期火舌刚性移动，不能代表连续外焰的形变，现已移除。新检查直接比较原生画面：共享流速归零时逐像素冻结，恢复后随外层同一时钟连续变化；保留三色、半透明、根部接触和边界检查。视觉自然程度仍通过动态预览人工核对。

最终验证：视觉检查24项、现有水火44项，共68项通过；无脚本或Shader错误。验证三色、半透明、根部连接、边界完整、画面冻结／恢复与真实战斗暂停／倍速／清理。前后动态对比为 `docs/previews/element_revision_20261015/fire-side-comparison.gif`；该对比只组合原生绘制帧，左侧为调整前、右侧为当前连续翻卷方案。

## 火焰当前随机性说明（2026-10-16）

当前火焰使用固定哈希产生的程序噪声，随传入的`effect_time`变化；没有每次灼烧随机抽取的种子，也没有逐帧重新抽随机数。同一尺寸、参数、战斗时间、强度及脉冲状态可重现同样的画面。调试器每轮从零计时，所以会重复同一套变化；正式战斗按全局战斗时间显示不同阶段，同尺寸同强度的多个目标会处于相同噪声阶段。本轮只回答随机性问题，未新增随机种子或修改火焰。


## 友军持续火焰与每跳瞬白（2026-10-16）

此前正式界面在事件触发和状态同步两处排除了治疗／防御，友军持续治疗、护甲虽正常结算，外观仍是旧版橙色闪光。现在删除这两处模式排除，正式战斗和战斗实验室共用`BattleFireVisual`的目标管理入口，每个目标只保留一团火；多份持续状态仍独立结算。

流程为“控制器发出真实`fire_tick`／`fire_finish`事件→火焰`pulse()`记录战斗时间→下一次显示同步按实际卡面矩形绘制瞬白→0.12战斗秒内恢复”。施加状态的`fire_burn`只显示火焰，不提前瞬白。`WHITE_FLASH_SECONDS`控制时长；`white_flash`节点保存每张卡独立的白色覆盖面，跟随卡面的位置和缩放，并保留像素切角。它不替换卡图、符文或死亡溶解材质，释放火焰节点时一并清理。

`Polygon2D`用于绘制带切角的白色面；每张卡单独一块，不把小队外接矩形作为整块闪光。`amount * amount`让白色快速衰减，读取`elapsed_seconds`而非独立Tween，因此暂停后冻结、倍速后同步加速。满血或护甲封顶时，真实结算事件仍可显示这一跳反馈；落空事件不触发。

新增`tests/fire_friendly_flash_test.gd`用真实Main、BattleLab、BattleController与原生画面验证三种模式：伤害／治疗／护甲实际结算、友军火焰、每跳瞬白、双卡堆叠、暂停与三倍速、恢复原色、五火终结及结束清理。

本次最终验证：友军火焰／瞬白52项、既有水火44项、原生视觉29项，共125项通过，最终日志无脚本或Shader错误。
