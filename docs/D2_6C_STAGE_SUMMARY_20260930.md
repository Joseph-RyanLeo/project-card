## 三层实现说明

1. 流程：新关建立资源实例和布局 → UI读取并处理手动部署／悬停 → 开战保存完整快照 → 命中资源写奖励账本 → 正常结算一次提交并消费本场资源 → 继续时创建下一关；中断走快照恢复。
2. 数据与入口：`OwnedCard.resource_shape`保存固定形状；`ResourceBoardState.level_resource_cards`保存双方自动资源，`deployments`保存统一部署表，`resources_generated`防重抽；`ResourcePreparationTray`绘制与命中；`BattleResourceState.current_health`保存战斗生命；`BattleController.mining_actions_remaining_by_runtime_id`保存每队次数；`BattleSettlementService`提交账本，`RunSaveService`保存与迁移。`GameDisplay.tscn`承载720p内部画布，`Main`串接所有流程。
3. 语法与原因：`RefCounted`表示自动管理引用的数据对象，使资源不会误入随从胜负判定；信号把UI事件交给Main；`affine_inverse()`将窗口坐标反算为托盘坐标，支持2K；`AtlasTexture.region`从图集裁小图。奖励先记账再提交，配合战斗ID去重，防止重复领奖。

位置调整入口：`scripts/main.gd:133`敌方资源区当前 `(6,171)`；`:134`我方资源区当前 `(1094,364)`；`scripts/ui/escape_pause_menu.gd:13`Esc当前 `(0,0)`。均为1280×720逻辑坐标，2K统一放大；收藏视角世界y=-360，我方资源区屏幕y=4。
