# 灰烬大卡包高度图预览

2026-10-27。当前袋身使用用户提供的125×188灰度高度图。调试入口已接入Esc；同日已将凹凸和固定光照预设接入正式商店卡牌包、只读检视、撕包及退壳。

## 使用

游戏或稀有商店按Esc →「卡包凹凸调试」。按Esc或右上「返回」恢复来源界面。也可打开`scenes/tools/PackReliefPreview.tscn`按F6单独运行。

左侧是原烫金，右侧是当前高度图计算结果；鼠标让两侧同步倾斜。袋身和金纹分别由两个0～2滑块控制，0关闭对应凹凸；默认袋身0.65、金纹0.45。临时试调只影响当前预览；正式卡牌包使用已确认的固定预设。

两张卡包之间有四项实时光照控制：

- 光源方向0～360°：表示光源所在侧，0°右、90°下、180°左、270°上；默认60°。
- 正面程度0.2～4：越小越贴近表面照射、坡面明暗越明显；越大越接近正面照明。默认0.20，这是方向分量比例，不是距离或真实高度。
- 亮度0～2倍：默认0.95倍；0关灯，1保持原值；同时作用于材质和素色光照，数据视图不受影响。
- 鼠标影响0～100%：0%使用固定方向，100%由鼠标反侧决定方向，中间值平滑混合。默认80%，即80%鼠标反侧与20%固定方向混合。

「恢复默认」同时重置两个凹凸滑块和四项光照。2026-10-27用户确认将60°／0.20／0.95倍／80%固化为启动与恢复默认的预设，脚本和独立shader默认值同步。控件保留临时试调；退出重进后回到这组预设，不保存临时光照草稿。所有调节只改变右侧材质，左侧维持原烫金对照。

面板现在明确显示固定／混合／鼠标反侧模式，并在每个控件下说明画面变化。鼠标影响100%时，方向滑块禁用并显示「方向由鼠标接管」，降低鼠标影响后恢复可调。鼠标进入光照面板时，沿用当前卡包倾斜，避免刚开始拖滑块就回正，掩盖正面程度的效果。

之前默认100%会把固定方向完全覆盖；鼠标离开卡包去拖面板时，跟随向量又回到零，使光源正对表面，此时改变正面分量也不改变方向。这是默认调试交互问题。当前80%混合预设保留固定方向的20%贡献；面板姿态保持继续避免调参时回正，未增加无关的光照补偿或额外高度。

右上可切换材质、高度、当前强度法线、素色光照及凹凸位置。高度图亮处高、暗处低；位置图黄表示相对高度，青表示局部凸脊，紫表示局部凹沟。高度与位置视图展示生成数据；法线与素色光照响应袋身滑块。

## 从输入到画面

`assets/card_ui/shop/relief_sample/body_height_input.png`是用户原图，直接逐字节复制保存，不缩放、不反转、不追加旧预设鼓包或五条折痕。原图SHA-256为`1624176820028249cde22eed49c6abd2688d07235c690063315eaf119043e7c3`。中央灰度143；四周窄亮边最高约181，所以窄边局部高于中央，按用户输入原样解释。

`tools/prepare_pack_relief_sample.py --height 新图路径`验证尺寸、灰度和透明轮廓，保存输入，并重算局部凹凸区域与金纹形状。省略参数时重用已保存的高度图。原先人为构造卡叠高台和斜折痕的代码已删除。

凹凸区域取当前高度与附近平均高度的差：比附近高标作凸脊，比附近低标作凹沟。局部均值只用于生成区域数据，不写回高度输入。金纹仍从原彩色卡包的三档金色独立提取，不把它叠入袋身高度。

`tools/generate_pack_relief_sample.mjs`调用Sprite Normals官方网页的公开worker及WASM生成法线。运行时给脚本传入本地worker和WASM路径；临时下载文件不进入游戏运行依赖。袋身关闭自动轮廓体积（volume=0），只根据当前灰度输入估算法线。官方地址、参数与SHA-256保存在`generation.json`，包含本次高度图校验值。

预览继续复用`InspectionCardSurface.update_pointer_force()`和统一透视。shader在同一坐标取样彩色原图、法线与凹凸区域，计算明暗及柔和反射。鼠标指向侧暗、反侧亮。袋身高光强度0.08、肩部柔和提亮参数0.065；局部增强区域改为从用户高度图重算的凸脊／凹沟权重，不再使用旧矩形支撑遮罩。

光照计算先把固定方向角转换为二维方向，再按鼠标影响比例与鼠标反侧方向混合；加入正面分量后归一化。法线明暗、金纹扫光和袋身宽反射都使用同一份混合结果，避免鼠标影响0%后还有某一层继续扫光。亮度最后只乘到材质／素色视图，原始高度、法线与区域颜色不乘亮度。

## 需要理解的写法

法线记录朝向，不能直接显示真实高度；平坦区域无论高低都朝向正前方，周围坡面才体现起伏。`normal.rgb * 2 - 1`还原方向分量，缩放横向分量后`normalize()`保持单位长度。

`dot(body.xy, light_direction.xy)`保留方向与坡度强弱，不把近零二维向量强制归一化，避免明暗突然翻转。三维光照Z分量由正面程度控制，默认0.20且始终大于0，归一化时不会出现零向量。肩部使用柔和混色降低发光边感。

光照方向使用`cos()`和`sin()`把角度转换成向量；屏幕Y向下而法线Y向上，所以转换时反转Y。`mix()`按比例平滑混合固定方向和鼠标方向。正面程度下限0.2，让完整三维向量始终非零。

滑块的`value_changed`信号调用`_update_lighting()`。鼠标影响在界面显示百分比，写入shader时乘0.01变为0～1；其他三项直接传入。恢复默认时使用`set_value_no_signal()`先批量同步控件，再统一更新材质，避免重复触发回调。

局部差`height - local_mean`的正负只用于分区标注与增强权重，不是第二份高度，也不是额外生成的折痕。原彩色素材最近邻取样，法线平滑取样，让像素边缘清晰而反光连续。

`fit_to_host()`将1440×960调试画布整体缩放到1280×720游戏逻辑画布，保持鼠标本地坐标与游戏窗口倍率。`close_requested`交由显示壳恢复来源处理模式和Esc输入。

## 正式商店与撕包接入（2026-10-27）

### 第一层：从商品到开包

三种主题的大／小卡牌包、五种行动定向小包统一使用当前凹凸与光照。陈列、未购买只读检视、成功购买后的撕口居中、手动／自动撕包和封条退场均沿用同一材质规则。参数为袋身0.65、金纹0.45；光源60°、正面程度0.20、亮度0.95倍、鼠标影响80%。贴纸包保留原封皮材质与翻页流程。

包装原图先按原生尺寸合成一次，封条与袋身从这份静态纹理取样。着色在各段的原图UV内执行，颜色与法线一起裁切、移动，再交给已有检视表面统一倾斜。正式陈列按2倍采样，放大检视与撕包按4倍采样；小包仍115×174、大包125×188，显示倍率、价格占位、鼠标命中及透视公式不变。外层关闭旧整面扫光与烫金，避免重复照明。

按住封口向前拉时裂口增加，未拉到底前往回拉则减少；可回到零，松手后保留当前裂口，重新抓取也可继续进退。曾经拖动过的手势即使回到原点，松手也不触发单击自动开包。完全拉到底进入退壳／揭卡后结束这次拖拽；单击和右键自动开包仍保留。往返拖动不重新购买、发卡或抽外观。

### 第二层：数据与脚本分工

- `shaders/pack_relief.gdshaderinc`集中固定预设和光照算法；调试入口与正式入口均调用`pack_relief_color()`，避免复制两份光照公式。
- `scripts/ui/pack_tear_art.gd`在陈列和开包中复用。`source_viewport`只合成一次原图；`material`在原图UV内计算凹凸与烫金；`configure_inspection()`绑定已有检视表面，读取同一平滑`force`。法线图与区域图按归一化UV适配大小包及主题包装，未新增主题专属高度图。
- `ShopOfferView._ready()`将卡牌包包装交给同一撕包图面，以零进度陈列；贴纸包沿用原`configure_inspection()`。
- `Main._open_shop_pack_inspection()`按4倍合成精度创建包装检视；`CardPackOpening.begin()`绑定原图与材质，原购买、保存和卡牌揭晓信号保持原流程。
- `CardPackOpening._advance_tear()`用本次抓取的`_drag_start`、`_drag_progress`计算新进度，不再取旧进度最大值；`_drag_moved`记住本次是否越过拖动阈值，释放时据此区分单击与回拉。

### 第三层：需要理解的写法

`draw_texture_rect_region(source, destination, region)`中的`destination`是封条现在画在哪里，`region`是原包装哪一块。shader继续使用`region`对应的UV读取颜色和法线，所以封条移动不会让光照滑回原来的屏幕位置。

`#include`将同一光照函数和uniform默认值放进两种shader入口；内层不再做透视，外层只做透视和颤动，避免旋转两次。离屏合成提高的是光影采样精度，原生素材仍用最近邻取样。

`progress`属性setter继续用`clampf(value, 0.0, 1.0)`限制合法范围；删除的是旧逻辑的`maxf(旧进度, 新进度)`单向限制。`_drag_moved`一旦变为true便保留到松手，不能只根据松手位置判断单击，否则往返到原点会误触自动开包。
