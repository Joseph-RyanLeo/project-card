## 一、整体流程

进入展览馆后在标题旁切换“卡牌收藏册／资源图鉴／贴纸图鉴”。资源和贴纸都保留每侧三行，每行四种独立条目，不占用实际收藏位；支持只搜索已发现名称／效果、按钮与PageUp／Down翻页。资源右键使用现有4倍检视，贴纸右键打开原图及可滚动效果正文；纹章、伤势、元素贴纸分开选择。

普通卡的生成源永久发现后，4倍详情中出现“衍生预览”按钮，展示全部可生成的基础版本，无须实际生成过。结果仍可右键4倍检视，Esc依次退回结果列表、生成源检视、收藏册、大厅。查看不增加发现，不创建本局卡牌、不入藏、不计分。

月露同时保留生成源预览和独立资源条目：预览不揭晓资源图鉴。齿轮废料也保留独立资源条目；现有规则已取消警戒机械废料遗愿，当前运行时没有其他正式生成源，故不恢复旧关联或制造新生成效果。将来新增正式源时再登记预览关系。

## 二、数据与脚本职责

- `scripts/data/gallery_catalog.gd`：扫描注册正式卡包的CardData资源，共130种可入藏卡、11种资源；资源含月露和齿轮废料。资源按品级降序、同级ID稳定排序，共享资源经任一归属包开放即可显示，避免迷宫主归属阻挡扭曲矿脉的四种共有资源。按已有贴纸库生成34种纹章、29种伤势、7种元素贴纸，合计70种，不混入开发演示牌。
- `scripts/ui/gallery_book.gd`：入口切换、原有收藏册、生成源弹层及逐层返回。切换或翻页先释放共享悬停与旧检视，只实例化当前双页内容。
- `scripts/ui/gallery_reference_book.gd`：复用同一双页布局展示资源、贴纸和衍生结果；`entries`保存本次筛选结果，`page_index`选择当前最多24种条目，`views`仅保存可检视的基础CardView。
- `scripts/ui/read_only_card_inspector.gd`：资源、普通卡、衍生卡复用相同基础卡构建和4倍检视。`derived_provider`只查询允许公开的生成结果，不承担生成效果。
- `scripts/ui/gallery_unknown_card.gd`：未知卡只创建背景、正确品级框和允许的图标，无名称、立绘或数值节点，不绑定拥有实例。

永久发现继续读`profile.discoveries.cards/resources/stickers`。卡包开放继续读`profile.unlocks.packs`；纹章和元素贴纸按`profile.unlocks.items`内对应单枚正式ID开放，伤势不新增解锁门槛。旧英文贴纸ID通过既有别名表匹配。任务商店及批量奖励发放尚属D3-4，不把Demo商店测试配置当作永久解锁，也不因发现记录反推开放状态。

发现计数三个分区独立，分母包含锁定正式内容。普通衍生卡不增加无法取得的独立发现分母。未开放贴纸隐藏；开放未发现贴纸只显示原图透明轮廓的剪影，没有名称、效果、提示文字或检视入口。已发现效果沿用现有贴纸资料查询（包括混沌贴纸最新说明），玩家界面不附带开发审阅元数据。

## 三、需要理解的Godot写法

`Callable`是可传递的函数引用：共用检视脚本向收藏册查询生成结果，避免让所有检视页面都依赖展览馆数据。`CONNECT_DEFERRED`让右键处理在当前输入分发后打开大卡；共享悬停仍只保留一份。嵌套预览暂时关闭生成源蒙版的输入监听，避免一次右键同时关闭两层。

未知贴纸用`ShaderMaterial`保留原纹理的alpha（透明度），只替换可见像素颜色，所以是原图轮廓，不会变成矩形色块。基础卡仅绑定共享CardData资源；检视用一个不初始化随机属性的只读OwnedCard壳，既不调用正式生成入口，也不消耗游戏随机数。
