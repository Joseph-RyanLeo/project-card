# 商店、事件新素材与落位烟尘

## 已确认的布局与行为

用户素材来自指定的“商店／商店”“商店／事件”两个文件夹。本轮只复制16张PNG，源PNG与Aseprite均未修改；游戏内使用AtlasTexture引用按钮或参考图的局部区域。文件、原路径与SHA-256见 `assets/ui/shop_event_20261020/素材来源.json`。

两个棋盘均为902×351原生像素。上半视角原点为(0,3)，对应世界棋盘位置(189,-3)；下半原点为(0,367)，对应世界位置(189,361)。二者换算成屏幕位置均为(189,-6)。普通事件及商店直接将棋盘放在Main的固定屏幕层，不加入WorldContent，因此战场的6像素越位与回弹不会传给棋盘。战斗准备介绍是例外：它固定在上半世界(189,-3)，切至下半视角时随战场移出屏幕，以让出我方阵容摆放区域。下半原点X从旧-1改为0，取消原稿适配遗留的1像素横移。商店独立的进出场动画保留。

商店左上双按钮：上按钮打开购物页，下按钮打开卡牌服务页。购物页复用现有报价、叠包、悬停倾斜、烫金与右键检视；新14×14金币与原生卢恩数字用于商品价格，刷新按钮直接显示当前费用，刮刀位于商品下沿。服务页同时显示左侧三个融合槽和右侧单卡槽。

右侧放入卡牌后，最多4枚纹章与3枚元素贴纸显示在周围8点，伤势仍留在卡牌上。只改变卡面显示，不实际移除OwnedCard中的槽位，因此卖价仍包含暂卸贴纸加成，也保留揭晓符文、伤势和法术耐久修正。未选贴纸时显示“出售”和所得金币；选中1～3枚时显示“提取”和2／5／10金币费用。直接点击执行，不再打开旧二次确认。未选贴纸随卡销毁，装备返还收藏；工具箱满时提取物进入既有临时区域。切页、取回或离店未成交时恢复原卡与贴纸显示。左右两种服务不能同时借用同一个卡牌实例。

事件初始只有中央166×153牌堆。点击后，三张166×136背面牌依次飞至屏幕中央并放大至2倍，中央牌中心为(640,360)，相邻牌间空隙36。背景在发牌期间逐渐压暗至70%，牌与普通文字暗示保持正常亮度。选择后，旧棋盘立即向上退场，其余牌飞开，选中牌翻正；描述棋盘落下后，选中牌缩回1倍并飞入左侧(116,108)，四周播放一次灰褐烟尘与细小亮点，右侧纸面上的正文及选项渐显。说明和选项限制在纸张内部，长内容可滚动。

烟尘参考用户提供的 `20261020004907-convert.mp4`：中心留空、周边烟团向外扩散并略向上翻卷、夹杂少量亮点，最后不均匀破碎消散。使用程序噪声Shader与像素亮点绘制，无需插件、生成图片或外部运行依赖。它是对参考形状与节奏的重建，不是从带背景视频抠取的原特效。

## 第一层：从输入到结果

- 点击购物／服务页签只切换显示，不刷新商品、不扣金币、不消耗随机数。拖卡到槽位附近松手后，原CardView从实际释放位置平滑移入槽内，来源保留虚影。
- 点击周围贴纸只改变选择集合。点击出售或提取才调用Main的原交易入口：重新验证资格、备份事务状态、处理卡牌／金币／工具箱，再写入存档。失败恢复全部数据。融合继续使用原三卡置换与融合演出。
- 点击事件牌堆只展示既有的三条路径，不重新抽路径。选中牌完成翻牌和归位后，协调器提交原选择事务；成功建立描述页并播放烟尘、淡入。若保存失败，则恢复原候选及随机源、释放退场模态层，重新显示可点击牌堆。
- 切换上下视角只移动WorldContent。普通事件与商店保持屏幕位置；选定战斗后的介绍板属于上半世界，随WorldContent离开下半屏幕。阶段切换时仍刷新迷宫界面；单纯切视角不会重建事件牌，避免中断淡入和烟尘。

## 第二层：主要脚本和数据

- `scripts/main.gd`：世界视角、商店报价和真实交易入口。`_execute_shop_sale()`、`_execute_shop_tear()`、`_execute_shop_exchange()`负责提交与回滚；提取额外重验1～3枚、原贴纸身份、重复选择和实际价格。
- `scripts/ui/shop_board_view.gd`：原生商店布局、双页签、融合提示、七枚环绕贴纸及“出售／提取”按钮。`_selection`只保存选中贴纸的实例ID，`_shown_stickers`只保存显示用快照。
- `scripts/ui/card_service_slot.gd`：五个槽共用的实际卡面借用、来源虚影、释放点吸附与归还。新增的`use_board_art`只隐藏旧槽轮廓，接收区域与吸附流程沿用原实现。
- `scripts/ui/card_view.gd`：`_service_stickers_detached`是显示状态，隐藏纹章和元素贴纸、显示底层符文；归还时复原。OwnedCard的`emblem_slots`、`rune_stickers`、`wound_slots`始终保留真实数据。
- `scripts/flow/short_maze_controller.gd`：读取真实迷宫路径、执行事件奖励、组织纸面选项，并决定何时重建界面。
- `scripts/ui/event_card_table.gd`：中央牌堆、三选一模态层、发牌／飞离／翻面／归位、介绍淡入。`busy`在演出期间阻止重复选择，`_paths`只使用已确定候选。
- `scripts/ui/event_landing_dust.gd`及`shaders/event_landing_dust.gdshader`：1.16秒的一次性烟尘；使用自己的视觉时间和固定分布，不调用游戏随机源。
- `scripts/ui/tabletop_art.gd`、`tabletop_header.gd`：共用原生图集按钮与固定屏幕坐标；顶栏读取真实层数、天数、轮次、失败保护和金币。

## 第三层：需要掌握的Godot写法

1. `position`相对父节点；屏幕位置还要叠加父节点变换。棋盘放在WorldContent外，才能在世界移动时保持稳定；两个世界坐标是同一屏幕点在不同视角下的换算结果。
2. `reparent()`移动同一个真实卡面，不生成另一张拥有卡。CardServiceSlot保存原父节点、位置、缩放和拖拽来源；结束时归还，避免卡牌或装备关系丢失。
3. 吸附先记录拖拽预览的真实释放位置，临时使用`set_as_top_level(true)`维持画布坐标，等待一帧容器排版，再恢复父节点变换并调用原移动Tween，避免先闪回来源一帧。
4. `AtlasTexture`相当于一张大图上的取景框；它不裁坏原PNG。`SIZE_SHRINK_BEGIN`让单卡保留原112×174命中范围，不被同一行较高的包装拉长。
5. 顺序Tween用于翻面、棋盘落下和归位，`set_parallel(true)`用于同时移动与缩放。协程等待当前动画结束后再衔接下一步；取消／重建界面时绑定节点的Tween会被清理。
6. Shader的`progress`只控制云团扩散、噪声翻卷与透明度；两像素取样保留像素颗粒。亮点与云团共用时间，但不写入玩法数据，也不影响事件结果。

## 战斗准备介绍遮挡修正（2026-10-20）

用户反馈选定战斗后切至下半视角，固定屏幕层的介绍板遮住我方战场，无法摆放阵容。此前“所有事件棋盘固定屏幕”的处理范围过大。

流程：协调器refresh()根据真实run.step识别BATTLE_PREPARE，将同一个MazeFlowPanel挂到WorldContent，局部位置由固定屏幕位置加上半视角原点换算为(189,-3)。下半终点的屏幕位置为(189,-370)，902×351板块完整位于屏幕上方；回上半后回到原屏幕(189,-6)。普通事件、天赋、三选一和商店继续使用固定屏幕层。

数据与职责：run.step只用于判断显示归属；Main.set_world_view()继续只移动世界；面板重挂不改事件选择、卡牌、存档内容或敌方信息权限。Godot的reparent(parent, false)保留同一个面板节点，再明确设置新父节点下的局部坐标，因此无需另写跟随动画或切视角时重建整页。

验证使用tests/battle_intro_world_anchor_test.gd：实际2K窗口中从收藏原生拖入我方前后排，检查普通事件／商店固定、战斗介绍随上半世界移出、返回上半恢复、真实存读档及开战，28项检查全部通过；日志为/private/tmp/project-card-battle-intro-anchor.log，无脚本错误。git diff --check通过，未运行全量测试。截图为previews/shop_event_20261020/battle_formation_uncovered.png。
