# 阶段 8：元素牌型效果与分层结算

阶段 8 在阶段 7 自动战斗闭环上接入精确浮点状态、五元素额外效果、主/副元素分层、持续状态、逻辑空间、结构化日志和程序化表现。五元素基础收益仍统一关闭；后续补充的同花两对复用三条档，顺子同时生成五种不连锁元素追加效果。

## 整体流程

1. 冷却完成时，`BattleController` 先为同一时间点的全部行动者选择基础目标，并建立基础 `BattleEffectEvent`。
2. 基础行动、同秒持续效果和疲劳进入同一个逻辑层，统一按伤害优先、治疗/护甲随后执行。
3. `BattleElementResolver` 按牌型给出最多两个有序元素组；控制器让所有行动者共同完成当前元素层的目标选择，再统一结算，然后才进入下一层。
4. 每个原始效果把精确公式交给 `BattleSquadState`。状态立即修改精确生命/护甲，并分别累计生命伤害、护甲伤害、治疗和护甲获得；跨过整数边界时发出可监听的整数提交事件。
5. 批次末尾统一确认治疗是否救回目标、最终死亡与击杀归属，再重算逻辑横向位置、前排遮挡和后续合法目标。
6. `Main` 只消费已经生成的效果事件，用同一份数据更新结构化日志、公式悬停和程序化元素表现，不参与规则判断；进入结算页后继续显示本场日志，重新开始时再清空。

## 已实现规则

- 五元素 2/3/4/5 档倍率、次数、持续时间与目标策略集中在 `BattleRules`。
- 火状态独立叠加，保存原来源；来源死亡后继续，目标提前死亡后取消，五火在最后一跳同时追加终结。火为主元素时，副元素跟随每次真实持续结算。
- 水严格按逻辑横向位置查左右最近目标，某侧不足不跨侧补位。
- 暗只追加基础行动之外的次数，持续锁定原目标；目标死亡后取消剩余追加。
- 光使用控制器随机源选择其他合法目标，固定种子确定，一轮不重复。
- 木与遮挡共用逻辑实体范围；木选择另一排横向中心最接近目标，三木以上穿甲并支持治疗/护甲双效果转换，五木同时升级伤害型主行动为穿甲。
- 葫芦按三条→对子，两对按可见第一组→第二组；所有组合继续乘真实浮点值，不在中途取整。
- 生命、护甲和元素数值全程保持精确值；卡面只显示四个独立累计通道提交的整数结果。
- 过量治疗与超过 999 的护甲不累计；0/上限、退场、战斗结束和重开执行边界同步。
- 击杀候选只记录精确生命首次跨过 0 的来源；同批治疗救回会取消。系统伤害没有卡牌击杀方。
- 后排被前排实体区间并集覆盖超过 50% 时受击权重减 1；恰好 50% 不触发，最低仍为 1。
- 每个原始效果立即写结构化日志，小数最多两位。“数值点伤害／治疗／护甲”完整短语带下划线且可悬停查看完整公式；弹窗按内容自适应宽高，并限制在窗口内。
- 结算页面继续复用战斗阶段的日志组件和公式数据，不复制第二套日志；点击重新开始后统一清空并隐藏。
- 程序化表现包括火闪光、水蓝线、暗紫线、木绿线和光黄白线；顺子与同花两对复用对应元素表现。每次弹道随机选择前段、中段或后段速度峰值，累计位移曲线统一从 0 到 1，因此途中变速不会改变总播放时间和最终落点。

## 主要代码职责

- `scripts/battle/battle_rules.gd`：牌型倍率、五元素各档配置、基础效果关闭入口、默认覆盖策略和逻辑空间阈值。
- `scripts/battle/battle_squad_state.gd`：精确生命/护甲、卡面整数、四个小数累计通道、整数事件与击杀候选。
- `scripts/battle/battle_formula_data.gd`：保存单个数值的完整公式快照。
- `scripts/battle/battle_effect_event.gd`：保存一次原始效果的来源、目标、层、模式、精确值、拆分结果和表现语义。
- `scripts/battle/battle_element_resolver.gd`：把牌型纯解释为有序元素组，不选择目标、不修改状态。
- `scripts/battle/battle_log_entry.gd`：把同一行动的多个效果组合为结构化日志，并为每个数值保留公式索引。
- `scripts/battle/battle_controller.gd`：统一时间轴、按层公平选目标/结算、持续状态、元素目标、逻辑空间、遮挡、死亡与击杀。
- `scripts/main.gd`：把效果事件映射到现有小队节点，更新卡面整数、日志、公式弹窗和程序化表现。
- `tests/stage_8_element_layered_resolution_test.gd`：覆盖五元素各档、五种行动、组合、持续状态、精度、归属、遮挡、日志与弹窗。

## 初学者需要留意的写法

- `RefCounted` 数据对象不进入场景树：公式、效果事件和日志条目只是数据，因此比 `Node` 更轻，也避免规则依赖画面节点。
- 信号转发：`BattleSquadState` 在小数累计跨整数时发信号，控制器再统一转发；卡牌效果以后只需监听事件，不必轮询数值。
- 两阶段批次：先生成整层事件数组，再执行数组。这个额外步骤是为了保证同一时间行动者不会因循环顺序获得先手。
- 逻辑空间与画面坐标分离：水、木和遮挡使用重算出的逻辑区间；Tween 只改变视觉位置，不会改变战斗判定。
- 字典配置当前用于可覆盖策略和各档参数；真正的运行时状态仍放在有明确字段的类中，避免所有数据都退化成难检查的字典。
