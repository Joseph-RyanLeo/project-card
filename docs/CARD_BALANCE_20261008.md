# 六张卡平衡更新（2026-10-08）

## 第一层：从战斗输入到结果

- 辎重驮夫：突击获得1金币；仅开场乡邻成立时立即开采1次。没有资源则机会失效，战中乡邻恢复、复活或召唤不补触发。原邻接生命光环删除。老狼使乡邻开采额外执行，金币仍只获得1。
- 铸甲师：相邻友军每成功开采1张资源，存活前排友军获得1护甲。双开采成功两张计两次，普通攻击击碎、开采落空不触发。来源在后排也只增强前排；前排包括自身，放逐单位不受益。原相邻死亡永久护甲成长和每场一次限制删除。
- 胆怯的步兵：同排其他友军实际行动后，获得1强化；旧5点贡献上限删除。自身行动消耗强化，其他排和敌军行动不触发。
- 伙夫：获得时从治疗和魔法中等概率确定一种。已有耀眼及突击火符文生命加值保留；已有实例保留原行动，不在读档时重抽。
- 悲歌诗人：其他非衍生物友军被消灭后，诗人左右相邻友军获得本场热诚+1；用户确认不包含诗人自身死亡。当前运行时已符合，卡面同步新短文。
- 盾墙列兵：已有真实耀眼保留，不重复添加。乡邻护甲额外+1保持。

本轮更新本地项目，没有导出游戏包，也未修改扭曲矿脉36张卡的文案；其原文已提取到 [当前文案清单](TWISTED_VEIN_CARD_TEXT_20261008.md)，供用户精简。

## 第二层：数据、脚本与时序

`.tres`保存卡面文案、词条和获得时行动候选。`ash_ledger_effect_samples.json`保存正式效果定义；战斗实验室的相关说明同步更新。

驮夫开采复用突击阶段和每场额度，只新增通用 `mine` 操作，调用控制器已有的 `execute_effect_mining()`；锁定资源、弹道、收获、开采监听与无资源行为共用既有实现，不转换成普通行动、不消耗普通开采次数或强化，也不触发回响。

开采成功时，`TwistedVeinRuntime.on_mining()`保存当刻相邻友军，先处理原有条件法术，再派发 `ADJACENT_ALLY_MINED`；随后继续巢母召唤等既有监听。效果执行器据此选择铸甲师以及前排目标，复用护甲获得修正。定义通过 `apply_armor_gain_modifiers`开启已有铁砧拦截器，盾墙的直接追加仍保持最后相加，验证得到1×2+1=3。

步兵在原有“其他友军行动后”触发上增加同排条件，强化仍由现有行动后生命周期消费。伙夫复用 `CardData.acquisition_action_types` 与 `OwnedCard.resolved_action_type`；正式Main的磁盘存档、读档和已部署小队均保持该选择。

## 第三层：GDScript写法

新增枚举放在末尾，避免改变已有枚举数字；字符串字典把JSON触发、条件、目标和操作转换成严格枚举，拼错会被正式目录校验拒绝。

`Array[BattleSquadState]`明确保存实际相邻单位引用。列表在成功开采当刻取得，后续召唤改变站位不会把新邻居误算进已经发生的事件；事件数据的深拷贝复制容器，仍引用原来的运行时对象。

`acquisition_action_types = Array[int]([3, 2])`中的3、2分别对应治疗、魔法。这个候选列表只供获得时抽取；确定后的数字存在拥有实例中，不修改共享卡牌资源。
