## 二、核心脚本与数据职责

- `scripts/data/short_maze_run_state.gd` 保存日轮与步骤，统一决定当前路径类型；流程判断使用类型而不是散落的旧轮数。
- `scripts/flow/short_maze_controller.gd` 协调选择、强化、哨位和英雄提示。强化先保存事务快照，再扣金币、写成长、推进、存档；任一步失败都回退。
- `data/demo2/short_maze_content.json` 的 `paid_events` 保存强化种类、三档价格与属性。沿用现有内容字段，不另建一套事件系统。
- `OwnedCard.permanent_growth` 保存该实例的永久成长；`is_new` 保存绿点状态。卡牌定义资源保存基础配置，不能把成长写进共享定义。
- `OwnedCard.get_battlefield_card()` 为同名队员提供不同的引用身份；`SquadData` 把身份绑定到原 OwnedCard。战斗和存档通过稳定实例 ID 找到真正的持有卡。
- `scripts/ui/card_service_slot.gd` 负责强化与商店的真实空槽显示和原生拖放接收，正式修改交回协调者。`scripts/main.gd` 复用既有检视、商店与结算入口。
- `scripts/ui/card_view.gd` 保存当前显示文字与数字 Tween；更新前后比较，只对发生变化的数字播放动画。
- `BattleEffectEvent` 保存哨位吸收明细，`BattleLogEntry` 负责文字输出；`BattleSquadState` 区分中毒统计，`SquadView` 使用伤势图标展示。伤害计算仍复用原战斗规则。
- 辎重驮夫效果位于 `data/demo2/ash_ledger_effect_samples.json`，正式卡面短文案位于 `resources/cards/baggage_muleteer.tres`。

## 三、需要理解的 Godot / GDScript 写法

**共享 Resource 与实例身份。** `load()` 取得的同一张卡牌定义通常是同一个 Resource 引用。原小队数组把相同引用视为同一队员，导致同名卡无法叠加。现在只在引用冲突时使用 `duplicate(false)` 提供另一个身份，并继续绑定原 OwnedCard。浅复制避免连效果定义等只读资源一起复制；实例成长、符文和贴纸始终由 OwnedCard 管理。

**原生拖放回调。** Godot 先调用 `_can_drop_data()` 判断合法落点，再调用 `_drop_data()` 提交。这两个函数共用正式条件，避免预览允许、提交却采用另一套规则。强化空位保存实例 ID，并临时保管原CardView；拥有权与部署绑定保持，退出归还节点。

**Tween 与坐标转换。** `create_tween().tween_property()` 在一段时间内改变属性。数字先放到 1.28 倍，再回到 1 倍；新的变化会取消同一数字尚未完成的 Tween，防止动画互相争抢。哨位把全局鼠标位置转换为落点区域的局部坐标，再移动到区域角落；库存坐标则保存进原哨位字典。

**事务快照。** `duplicate(true)` 为字典保存独立副本，防止正式操作同时改掉回退数据。永久成长使用 OwnedCard 正式快照恢复，以保留卡牌实例和阵容之间的引用关系。结算查看按钮只切换界面可见性，不再调用奖励事务。

## 2026-10-05 追加修理：流程与实现

### 1. 整体如何运作

强化事件右侧与普通商店“卡牌服务”均显示99×136像素卡牌轮廓。把收藏或合法战场卡牌拖入后，槽中显示原OwnedCard；这个操作临时把原CardView移动到槽内，来源不再重复显示，OwnedCard拥有权保留；支持槽内抓取归还，退出自动归还。商店自动切到收藏视图，左侧按目标显示出售收益与已有撕卡服务的资格，再进入原确认流程。撕卡仍销毁宿主、返还选中的贴纸；不是保留卡牌的摘除服务。成功交易立即保存，失败恢复卡牌、金币、贴纸、部署和装备归属。

符文揭晓或纹章粘贴时，先计算新的目标属性，再从检视中正在显示的旧值开始滚动。同一个0.64秒Tween同时控制数字与尺寸：前半程放大至1.28倍、后半程缩回。重复通知相同目标时沿用正在运行的Tween，不跳到终值、不重启。

日月星、哨位和装备的取消路径共用原图标回位表现。单击携带与原生拖动先取手持预览的实际全局中心，取消或非法放下时保留逻辑绑定，让图像在0.28秒内回到原位置。只有合法落点才提交转移；装备非法落点不会再自动卸下。

### 2. 关键脚本与数据

- `card_service_slot.gd` 替换原强化专用投放脚本，绘制空槽、显示选中实例、发出`card_selected`信号。资格由`accepts_card`回调提供，槽本身不执行强化或交易。
- `short_maze_controller.gd` 沿用强化资格与提交事务；`main.gd` 的`_shop_service_card_id`保存商店目标实例ID，`_capture_shop_card_transaction()`和`_restore_shop_card_transaction()`处理共用快照和回退。
- `CardView._squad_*_preview_target`保存最终数值，当前preview保存逐帧显示值；`_animate_battle_number()`统一数字和尺寸的时间轴。战斗原有数字动画仍使用原时长。
- `EquipmentIndicator.play_return_feedback()`操作图像子节点，根节点继续作为固定命中区域。`CelestialIndicatorController`与Main分别结束日月星／哨位携带和装备携带，并读取原生预览位置。
- `_build_collection_cards(..., reuse_unchanged)`在成功出售／撕卡时保留未改变实例的节点，只创建新增可见卡和部署状态改变的卡面、移除失效节点。成长更新、读档和回退仍完整刷新，防止旧视觉状态残留。
- `d2_8_service_animation_test.gd`用正式GameDisplay和真实鼠标输入验证行为并采样。`tests/performance/service_profiled_main.gd`仅通过`super`包住真实子步骤计时，不替换业务逻辑。

### 3. 初学者需要理解的写法

**Callable与signal：** 空槽用`Callable.call()`询问当前场景能否接收这张卡，再用信号交给协调者处理。于是强化和商店共用同一个节点，却各自保有自己的合法条件和规则。

**并行Tween与delay：** `set_parallel(true)`让数字滚动和放大一起开始。缩小步骤通过`set_delay(duration * 0.5)`等待半程再开始，因此两种动效属于同一个Tween。按属性键保存Tween，并在目标未变化时直接返回，可以避免频繁刷新导致动画不断重新开始。

**全局坐标转局部坐标：** 预览位于另一层节点，其坐标不能直接写进原图标。`get_global_transform_with_canvas().affine_inverse()`将预览中心转换到原图标的局部坐标，再减去图标半尺寸，得到返回动画起点。

**事件触发刷新与节点复用：** 原来库存每帧重复扫描并同步；现在阵容变化后才同步库存，逐帧只记录必要的部署图标位置。交易只删除目标卡，因此用OwnedCard引用查找可复用卡面，并用`move_child()`调整页内顺序；已改变的部署灰影重新创建，避免错误保留不可交互状态。

- 最终原生1280×720窗口专项49项通过，覆盖强化／商店空槽、真实携带选卡、确认取消、符文与纹章同步数字、六种指示物取消／非法放置组合、节点复用后的真实抓取、交易保存与失败回退。
