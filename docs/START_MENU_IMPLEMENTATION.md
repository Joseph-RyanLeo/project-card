# 四层菜单与存档路由

更新：2026-11-02，D3-1收尾及后续可读性、命名调整。沿用现有像素背景、1280×720逻辑画布与既有跨界面加载动画；菜单文字已统一使用项目内精细黑体，没有安装依赖或新建美术素材。

主菜单上方显示中文名「余烬秘渊」，下方以较小字号显示英文名「Embersea Arcana」。名称统一读取`project.godot`中的`application/config/name`与`name_localized`，不在菜单重复维护另一份名字。固定原有`user://`目录，使应用改名后仍能找到原来的存档和设置；macOS改名前后实测路径均为`~/Library/Application Support/Godot/app_userdata/Project Card`，Linux沿用原小写`godot`目录。

## 1. 玩家操作流程

启动主菜单只有「继续游戏／开始游戏、选择存档、设置、退出游戏」。完全没有存档时显示「开始游戏」，点击后自动创建第一档并进入局外大厅。存在存档时显示「继续游戏」，优先进入上次成功使用的档；上次使用档已删除时选择第一个仍存在的档。损坏档不会被静默当作空档覆盖。

存档选择显示三个位置及其本局／局后总结／待选卡／待确认收藏／局外状态、积分和可用进度。点行仅选择，点击「进入」才新建或恢复；「删除」仍需确认，并清除该档JSON、临时、备份与诊断文件。「返回」只关闭选择页。选择位置与上次成功使用位置独立保存，单纯浏览另一档不会改变主菜单「继续」的目标。

进入存档统一按保存阶段分流：

1. `active`：创建Main，直接读取原本局，不提前初始化另一局或赠卡。
2. `selection`／`preview`：直接恢复待完成收藏面板与原选择，不创建Main，也不开放新局／商店入口。
3. `hub`：进入该档局外大厅，显示档位和积分，提供「开始新一局、展览馆、迷宫商店、设置、返回主菜单」。展览馆与迷宫商店的正式系统尚未接入，入口明确禁用，不显示可点击却无反应的入口。

空档只保存局外数据，既不创建迷宫，也不提前发初始卡或永久发现。点击大厅「开始新一局」才初始化并保存本局；保存失败回到原大厅，可以重试。当前新局继续沿用Demo2现有八天流程与原5张初始卡；完整教程、任务选择、英雄选择、供给限制由其余D3阶段接入，不把菜单完成等同于教程已上线。

对局Esc首页为「继续游戏、设置、开发工具、保存并返回主菜单、放弃本局…」。设置和工具各为子页；在子页按Esc只回暂停首页，保持暂停，继续游戏才释放Esc持有的暂停。原特效／卡面／字体／战斗工具、受击优先级、诊断导出和启动还原都保留在工具子页。对局保存返回直接到启动主菜单，不进入局外大厅，不能借此绕过本局购买资格。D3-2已接通明确二次确认后的放弃结算；保存返回仍不结束本局。总结、完整选卡与集合阶段见[D3-2说明](D3_2_RUN_END_IMPLEMENTATION.md)。

## 2. 主要脚本与数据

- `scripts/ui/game_display.gd`负责进入、恢复、保存和退出路由。`slot_progress`持有当前档的局外数据，`_slot_checkpoint`保留磁盘根数据；`main_screen`只在需要运行本局时创建。`start_slot`进入档位，`start_new_slot_run`手动开启新局，`return_to_start_menu`保存后退出档位。
- `scripts/ui/start_menu.gd`负责启动页与三档选择面板。`scripts/data/run_slot_service.gd`用`selected_slot`记选择位置，用`last_used_slot`记上次成功进入位置；两者只属于本机导航偏好，没有共享游戏进度。
- `scripts/ui/slot_hub.gd`负责档内大厅及原收藏阶段摘要，发出新局、返回、设置和收藏确认信号。布局不承担存档写入；`GameDisplay`收到信号后统一保存，失败恢复原局外快照。
- `scripts/ui/escape_pause_menu.gd`负责暂停首页、设置和工具子页，继续沿用Main的暂停归属逻辑。`close_subpage`返回是否只需关闭子页，让Esc不穿透成继续游戏。
- `scripts/ui/menu_style.gd`共用原背景、字体、暖金色边框及按钮样式；`scripts/ui/game_settings_panel.gd`共用设置控件，避免主菜单和对局设置各维护一份不同的选项。
- `scripts/data/game_preferences.gd`保存主音量与窗口模式；卡牌文字模式复用原`card_text_display_settings.gd`，保留字体调试参数。偏好保存于本机`game_preferences.cfg`、`card_text_display.cfg`，独立于三档；删档不清除设置。设置保存失败会明确提示当前已生效、偏好未能写入。
- `scripts/main.gd`增加`initialize_maze_run_on_ready`，正常新局沿用原初始化，读档则跳过预开局；`BattleAudioService`的主音量操作复用为静态方法，菜单没有另建一套音频逻辑。

## 3. 保存与恢复边界

仅局外的新档JSON保留`schema_version`及完整`profile_progress`段；尚不存在本局字段。开启新局成功后，原本局字段与局外段一起保存。已有完整Demo2／D3本局仍由原Main读档／迁移流程校验，未改名或丢弃旧字段。

收藏阶段或大厅没有Main时，保存会复制原根数据，只替换已校验的局外段，继续复用原临时文件、备份与原子覆盖服务。收藏有Main时仍使用原保存入口。失败不移除有效主档，也不将待确认收藏提前提交。

所有菜单都能返回或重试；保存返回失败保留原对局和暂停状态，开启新局失败保留原大厅进度。关闭窗口与退出按钮同样先保存当前档位，包括只有大厅／收藏数据的状态。处于跨界面加载时不接受另一轮进入请求。

## 5. Godot写法说明

界面用信号表达「玩家想进入／返回／确认」，显示壳负责保存后决定是否切换，避免按钮绕过失败处理。`Callable`让同一过场动画复用不同进入动作；`await`等待实际初始化和过场完成后才继续输入测试。

局外数据是`RefCounted`，可以在没有Main场景时保留；运行一局才需要完整节点树。`duplicate(true)`复制根数据与嵌套选择，保证失败动作能恢复原值。隐藏Main时还会关闭其Esc输入，因为暂停菜单使用`PROCESS_MODE_ALWAYS`，仅隐藏画面并不足以停止输入。
