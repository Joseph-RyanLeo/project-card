# 2026-10-02 卡顿修复与验证

第二轮针对 Windows 复测后剩余翻页和结果页停顿的分析、修改及验证见 [第二轮报告](PERFORMANCE_FIX_SECOND_PASS_20261002.md)。

## 本轮结果

修复已确认的导出包符文 PNG 读取失败：像素来源改为 Godot 导入纹理 `Texture2D.get_image()`，只在第一次查询时建立透明度和有效像素计数缓存。无效资源会明确报错一次，不再按每个像素重复读取；正常导出包覆盖面积仍为409像素、70%阈值仍为287像素。

另外减少了正常资源情况下的重复工作：

- 未刮槽共用只读空遮罩和两份着色器材质；首次实际刮除才分配该槽独立纹理/材质，后续擦除更新现有纹理。
- 遮罩从擦痕字节直接展开，跳过零字节，避免逐像素调用命中查询和 `set_pixel`。
- 开始战斗时合并状态与结果统计清理，只刷新一次小队；首次成功结算的收藏只重建一次，资源板不重复刷新。
- 商店一次刷新共用卡牌定义和合法候选；购买时仍重新验证持有资格。关闭商店不重建已经隐藏的商品。
- `drag_preview_ms` 补计原生长按拖动，点击携带维持原有计时，不重复相加。

当前没有确认纯卡包悬停存在独立根因；本轮处理了商店刷新/离店阻塞，保留只让鼠标指向的包晃动的交互。伙伴 Windows 机器上的体感与纯悬停需回测。

## 实现学习

### 1. 输入到结果

卡面需要覆盖数据 → 从打包纹理读取像素并缓存 → 未刮槽共用空遮罩 → 第一次刮除后转为独立遮罩 → 更新擦痕 → 达到70%或退出模式揭晓。收藏、虚影和检视仍绑定同一个OwnedCard真实实例；付款和战斗规则没有改动。

### 2. 关键脚本和数据

- `RuneRevealCoverStyle`：`_cover_alpha` 保存圆形命中区域，`_opaque_pixel_count` 保存409，`_empty_mask_texture` 与 `_empty_mask_materials` 保存只读空资源。
- `CardView.refresh_rune_scrape_cover`：识别共用空纹理并在第一次刮除时换成独立资源，覆盖图与底层元素同时换材质，后续仅更新纹理。
- `OwnedCard.rune_scrape_masks`：仍是每槽独立、按位保存的擦痕；`rune_revealed` 决定是否实际揭晓。
- `Main`：控制商店一次刷新用一次候选计算，减少阶段切换重复构建，补原生拖动计时。
- `SquadView`：状态和结果统计可合并清理，最后统一刷新卡面。

### 3. 不熟悉的写法

`static var` 属于脚本类，多个卡面共享同一份缓存。适合不会被修改的空遮罩；真正擦痕必须独立，不能对共享纹理调用 `update()` 或修改共享材质参数。

`Texture2D.get_image()` 获取Godot导入资源的像素；`globalize_path()` 只生成普通磁盘路径，不能取出PCK中的原始PNG。`PackedByteArray` 每字节保存8个刮痕位，`bits & (1 << bit)` 用来检查某一位是否已刮，避免逐像素对象创建。

计时测试继承正式脚本，以 `super` 调用真实实现后记录时长，不替换业务逻辑。候选只在一次商店刷新中传递，避免长期缓存把持有资格冻结。
